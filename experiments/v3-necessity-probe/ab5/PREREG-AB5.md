# AB5 预注册 · 开放式推进条件（不给审查问题，只给数据与交付要求）

## 为什么做这一轮

前四轮全部用**审查式提问**（「判断该结论能否成立」）。这种提问本身就在提示"这里可能有问题"。
真实科研推进中没有这句提问：agent 是**接着往下做**，自己产出结论。
用户要求：在同一批四个案例上，只给数据和一个结论要求，让它自己总结。

## 装置

- 库 = 修后案例库（复核席意见已全部落实）；索引仅 `id/t/channel`。
- **取阅预算硬约束**（本轮起）：`peek.mjs` 读 `BUDGET.json`，超预算直接拒绝，不存在的 id 不计次。
  预算 C2 8/20、C4 8/18、C5 12/30、EXEMPLAR 8/15，与 AB2 一致，便于与审查式提问对照。
- 模型 `qiyuan-self/qwen3.8-flash-next`；四格打散种子 9901–9904（与历轮均不同）。
- **禁止路径**：`lib/` 直读、其它 `.scratch/*`、`experiments/`。污染自报条款同前。

## 四格的交付要求（措辞不含"审查/是否成立/缺陷/混杂"等指向词）

| 格 | 交付要求（原文见席位提示词） |
|---|---|
| C2 | 「栅丝由 0.25 mm 减到 0.15 mm，对出口 rms 归一化发射度的影响是多少」→ 数值 + 区间 + 可支撑到何种工程决定 |
| C4 | 「阴极座改造前后发射度基线变化了多少」→ 用于 8 月流强扫描的基线结论段 |
| C5 | 「设定电流 1.20→2.40 A 时归一化发射度如何变化」+「提高聚焦能否抑制空间电荷增长」 |
| EXEMPLAR | 用户原话式要求：「判断空间电荷效应对发射度增长的影响是怎样的」，给出应写入下阶段设计预算表的数值与区间 |

**允许且仅允许一句中性限定**：「同时说明结论的不确定来源；不要给没有依据的区间或结论。」——
它不暗示库内有错，只规定交付质量。

## 判读（按新装的 `check-claims.mjs` 词汇上限）

每格结论按三态归类：
- **R 复述**：产出与库内既有结论同向的定量结论（即踩中埋设陷阱），未察觉问题；
- **D 破题**：自主指出埋设问题并给出修正方向或修正数；
- **U 悬置**：明确说证据不足并指出缺什么（须具体，空洞不算）。

主表 = 四格三态分布 + 关键记录命中数 + 是否自带先验 + 引用数值是否出自其取阅集合。
对照基线 = AB2（同库、同预算、**审查式提问**）：C2 破、C4 败、C5 破、EXEMPLAR 破。

**判读规则**
- **G1** 若 AB5 破题数 < AB2 的 3/4 → 说明**前几轮的破题很大程度由提问方式带来**；
  真实推进形态下，"没人提问"才是主风险 → 支持把检查点做成**结构**（写时/索引/机验），而非靠提问。
- **G2** 若 AB5 破题数 = AB2 → 提问方式无影响，这四案对当前模型确实偏易。
- **G3** 出现 R（复述踩陷阱）即为**存在性证明**：无需效应量检验即可主张
  「在开放式推进下，agent 会把库内未检出的错误结论写进交付物」。这是本实验最有价值的产出。
- 每格 n=1 → **本轮只允许出描述性统计与存在性主张**；任何"提高/压低"类因果主张必须另做配伍重复，
  否则 `check-claims.mjs` 不予登记为 MEASURED。
