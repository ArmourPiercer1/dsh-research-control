# H/S/R 科研认识基础设施：顶层架构讨论基线

> **状态：DRAFT-PROPOSAL（讨论基线，非冻结实现契约）** · 2026-10-27  
> 本文整理 PR #9/#10、后续 PoC 以及 2026-10-27 的设计讨论。其目的在于**先冻结讨论的问题域与职责边界，再逐项裁决语义细节**。已讨论通过的方向性原则与尚未决议的实现选项必须区分。本文不改变 V1 Current 契约、已有 ADR 的正式状态、Schema、运行时 API、数据、权限或 CI；不批准 V3 实施及任何 LIVE_* 接入。

## 1. 使命：我们要管理的是什么

系统的研究认识层服务于一个明确目标：

> 在认识会随时间修订、不同主体可以同时持有不同意见的情况下，忠实保存**已登记**的研究活动、陈述、评价、论证及其演化，使研究者和 Agent 能够在明确来源与语义边界内追溯、理解、检查和复盘科研历史。

系统维护的是**研究主体的认识记录**，而不是一份由系统裁定的客观科学真理目录。

### 四个核心问题

| ID | 需要解决的问题 | 预期可回答的问题 |
| --- | --- | --- |
| P1 认识变更 | 研究者会修订、撤回、重新解释已有认识 | 当时登记了什么？后来如何改变？ |
| P2 意见并存 | 不同主体在同一时刻可以对相同命题有不同判断 | 各主体的观点和依据分别是什么？ |
| P3 可变认识下的论证 | 证据、前提或解释修订后，相关论证需要可检查、可追溯 | 哪些明确登记的论证路径引用了受质疑对象？ |
| P4 长期可理解性 | 后来的研究者/Agent 要理解结果、决定和历史上下文 | 结果从何产生？当时明确声称采用了什么依据？ |

P1–P3 是科研认识语义问题；P4 是让这些能力长期可用的跨系统目标。**不新增“自动科研判真/研究路线优化”作为基础使命。**

## 2. 三个职责正交的核心系统

**正交指保证与职责分离，不意味着不同数据库、微服务或者三份事实真源。**

| 核心系统 | 核心问题 | 必须保证 | 不承诺 |
| --- | --- | --- | --- |
| **H — History（历史记录）** | 系统实际登记了哪些变化？ | 记录来源可追溯、历史版本不可被静默改写、可按明确时间语义回放 | 历史完备、未记录事件的还原、客观事件必然真实 |
| **S — Semantics（语义）** | 我们讨论的对象及陈述究竟是什么意思？ | 身份、词汇、语境与精确修订的含义稳定可追溯；允许澄清和分歧 | 科研陈述真实、不同模型天然等价、语义澄清程度保证单调增长 |
| **R — Reasoning / Argumentation / Verification（论证、校验、可选形式化）** | 研究者登记了哪些证据、推理、评价及接纳？ | 精确引用、可检查的已声明论证结构；任何验证附带保证范围 | 无条件推出科学真理、替主体接受/否定命题、强制全面形式化 |

### 2.1 H：历史系统

**负责：**
- 保存提交、活动、来源、陈述、确认、评价、决定和修订等**已登记事件**；按追加历史维护稳定 ID 与不可变 Revision。
- 区分登记顺序、声称发生时间（occurredAt）与记录时间（recordedAt）；处理迟到登记、补写笔记、乱序导入，不从时间先后自动推断因果或“当时已知”。
- 给出历史回放、指定记录截点下的状态视图、来源回指、缺失/未映射/不确定信息报告。投影可重建而非独立真源。
- 外部资料可用 URI、哈希、快照或恢复配方登记；外部文件删除、校验失败或无法重建时**如实提示、不伪造、不阻断整个历史服务**。

**不负责：**判定原始科研描述是否科学正确；根据补录事件改写过去研究主体的实际认知；担保原始研究工件永久可得。

### 2.2 S：语义系统

**负责：**
- 为 Concept、研究对象、WorldContext、Scope、ResearchFinding、Assertion/Revision 等提供稳定、版本化、可追溯的身份与解释；复用语义相符的 W3C 标准名。
- **L0** 保存有来源、可能不完整的规范化自然语言信息，可继续研究；**L1** 建立足以跨 Agent 精确引用的稳定语义，不意味着证据充分、证明有效或 Fact 已接纳。
- **AssertionID 表示一条陈述的历史连续性，不表示不同 Revision 语义等价**；AssertionRevision 保存精确含义。后续语义变化不得隐式重解释历史 Revision。
- World/Scope 与 Concept 版本参与精确陈述的含义；不默认跨 World 迁移；允许明确的 UNKNOWN（未知不是自动否定或自动普遍成立）。
- 研究基础选择按**研究维度及其可选项**组织：已有核心对象通过注册与 ResearchFrame/ContextProfile 等候选机制引用；新维度导致的覆盖复核是**结构性待审提示**，不自动修改旧陈述或形成科学证明义务。

**设计目标而非强制不变量：**术语、对象和研究语境在持续讨论中逐渐清晰；出现歧义或分歧时，保存明确的新修订/映射及不同意见，**旧版语义保持可解释**。

**不负责：**证明自然语言与物理现实一致；凭相似度自动合并两个命题；要求所有 L1 对象进入严格形式化或全局核心对象接受/拒绝矩阵。

### 2.3 R：论证、校验与可选形式化系统

**负责：**
- 区分来源关系（PROV）、局部证据意义（EvidenceRelation）、多前提论证（Argument）、主体评价（Assessment）及正式接纳（FactStanding）。
- 每条论证在明确声明的前提、条件、目标精确 Revision 和推理方式上进行记录；可检查引用/规则、登记非阻断 ProofObligation，进行限定范围内的依赖及选择性影响分析。
- 允许多主体分别作出不一致的 Assessment；FactStanding 是**有责任主体、时点和范围的可修正接纳声明**，不是命题本体的真值标志。
- 需要时接入形式化规则、统计方法或 Lean 等证书，**严格报告它们实际证明/检查了什么**，不将类型检查、数学证明、统计结果自动提升为物理模型适用或普遍科学事实。

**不负责：**仅凭一个结果自动形成完整 Argument；仅凭关联边或时间先后推导因果；依赖变化后未经授权自动撤销研究主体的接纳；调度科研 Agent。

## 3. 三系统的连接方式与共同底座

~~~text
外部研究者 / 科研 Agent / 现有 V1 工作流与治理面
                │ 记录、查询、审查、授权
        统一身份与 ResearchSpace 访问边界
                │
      ┌─────────┼─────────┐
      │ H 历史  │ S 语义  │ R 论证与校验
      └─────────┼─────────┘
                │
     同一权威事件记录 + 版本化对象引用
                │
          可重建的各类投影
                │
    （按需）关联检索 / 图视图 / 研究辅助
~~~

该图是**职责结构**而非执行顺序：H 记录 S/R 的变更，S 给 H/R 的对象提供精确语义，R 引用 H 中事件和 S 中特定语义版本。三者不各自另造一个独立的科研事实真源。

### 共同不变量

| 不变量 | 要求 |
| --- | --- |
| X1 记录与真值分离 | “有人提交/认为/接纳 P”不自动意味着现实中的 P 成立 |
| X2 不可变历史 | 修订、补录、撤回和争议采用新记录；旧原文及精确版本可回放 |
| X3 精确引用 | 科研论证、评价和历史决策可指向确切 Revision；不自动漂移到 latest |
| X4 关系不得洗白 | PROV 派生≠逻辑证明；统计/设备关联≠因果；DecisionBasis 自述≠实际决策因果 |
| X5 分歧并存 | 同一精确命题允许不同主体同时持有不同立场；不强制唯一全局观点 |
| X6 不完整性显式 | UNKNOWN、缺失文件、断链、无法映射和截断应可查询；不自动脑补或假设不存在 |
| X7 ResearchSpace 隔离 | 不同 ResearchSpace 的数据不能互相访问；同一空间内可按授权共同引用；Project/Topic/Workstream 是组织筛选，不是跨空间共享权 |
| X8 人的裁决权 | L1 语义确认、科学接纳及正式科研决定各有可归因主体；结构检查不自动替代其裁决 |
| X9 渐进兼容 | V1 的 Current 契约、权限、工具与历史保持权威；V3 不因本文自动修改任何运行时 |
| X10 W3C 精确复用 | 同义采用 PROV/SOSA/SKOS 等正式术语；不同语义保留 dsh 扩展；RDF/SHACL/JSON-LD 不成为科学判真器 |

**统一的身份、鉴权、ResearchSpace 边界是三系统共同遵守的横切基础设施，不是第四套科研认识系统。** 现有 Plan/Task/Run/Gate 等业务工作流继续作为独立控制面；不把科研执行编排强塞进 H/S/R。

## 4. 典型对象如何分工

| 对象/机制 | 主要归属 | 与其他系统的关系 |
| --- | --- | --- |
| Event、Revision、Provenance、记录时间、快照、缺失状态 | H | S/R 通过精确来源引用读取 |
| Concept、WorldContext、Scope、ResearchFinding、Assertion/Revision | S | 语义变动由 H 留痕，R 引用精确版本 |
| ResearchFrame / ContextProfile（候选结构） | S | 研究维度/选项和语境对齐；H 记录修订，R 可用作显式前提而不自动采纳 |
| EvidenceRelation、Argument/Revision、ProofObligation | R | 依据来源由 H 提供，命题含义由 S 提供 |
| Assessment、FactStanding | R | 记录**主体的评价/接纳**；其历史由 H 保存，目标由 S 确定 |
| DecisionBasis（决策笔记本） | H + S | L1 稳定地保存“主体声称当时考虑什么”；**不进入 R 的正式推理依赖图** |
| Inference Graph（论证关系） | R 的基础语义 | 关系要可保存；物化图、查询加速和可视化可后置 |
| Research Association Graph、联合召回、自动异常发现 | 高级能力 | 只读取 H/S/R 已登记事实与关联，不能自动晋升成论证或科学真值 |

### 不同记录不会互相替代

- **Observation/Result 修正**：保存当时实际执行的解析活动和结果；后续可追加“某解释/使用方式已被修正”的 Assertion/Assessment。合法来源记录不等于结果的物理含义必然正确。禁止追溯覆盖旧结果，也不要求系统自动发现解释错误。
- **DecisionBasis 自述**：历史状态依据明确登记的事件及其时间语义；笔记仅保存研究者声称考虑了什么，不代表全体真实心理因素，也不自动生成 Argument。
- **同题不同意见**：同一 AssertionRevision 可以有不同主体的 Assessment；某个项目/责任主体的 FactStanding 不吞并其他主体的意见或旧历史。
- **新增研究维度**：如果 ResearchFrame 增加“扫描波形”这一需考虑的维度，旧 Profile/AssertionRevision 仍原样存在；当前覆盖检查可提示“尚未处理新维度”，不据此宣布旧命题为假。

## 5. 基础能力与高级能力的分界

**基础层必需**：事件/时序与回放；可溯源来源关系；对象/概念与准确版本；L0/L1 语义；主体及研究语境；证据和论证的基本表达与精确引用；多主体 Assessment、正式接纳历史；最小结构、版本与明确规则检查；统一 ResearchSpace 边界。

**高级层按需引入**：Research Association Graph、跨图灵活检索、自动建议和异常发现、图数据库/图可视化、概率推理引擎、L2–L5 深度形式化、自动研究路线生成。高级层不建立第二真源，且不得无审查将关联结果提升为科学结论或正式 ProofObligation。

**注意**：论证所需的依赖关系本身属于 R 基础语义；它的复杂图物化、遍历优化与融合召回不是三系统成立的前提。

## 7. 已达成的方向共识、待裁事项和讨论顺序

### 已达成的**方向性共识**（本 PR 只作记录，不将其自动升级为正式 ADR）

1. H/S/R 是科研认识基础设施的三个核心正交职责；权限/ResearchSpace 是横切边界，关联检索等为高级功能。
2. 系统忠实保存研究者登记的认识及评价，不裁决普适科研真理；多主体意见可以并存。
3. 历史不追溯覆盖；来源、语义、论证与接纳严格区分；L0/L1 是渐进语义，不是真值等级。
4. AssertionID 表示**陈述历史连续性**，不是跨 Revision 语义等价；精确推理/审查应锚定 Revision。
5. DecisionBasis 是仅用于历史复盘、具备 L1 语义的决策自述，不是实际论证依赖。
6. 研究基础选择按“**研究维度及其可选项**”组织，而不是要求每个 Assertion 对全局全部核心对象做接受/拒绝矩阵。
7. 外部科研文件缺失应成为可查询的客观缺失状态，不阻断整个系统，不承诺无条件重建。

### 尚未冻结的基础问题（后续分专题裁决）

| 议题 | 需要明确的语义边界 | 主要归属 |
| --- | --- | --- |
| **S1 命题/语境身份** | 同一 Assertion 的合法修订边界；Revision 精确含义；ResearchFrame 与 ContextProfile 的必要性及兼容规则；跨 World 映射是否、如何登记 | S |
| **S2 多主体意见** | Assessment 和 FactStanding 的主体、授权、分歧并存、接纳与撤回语义 | R + S |
| **S3 证据与论证** | EvidenceRelation、Argument 的前提/依赖及攻击结构；选择性影响与科研接纳决定之间的边界；可选形式证书 | R |
| **S4 历史与时间** | 迟到登记、事件时间与登记时间、查询历史截点、DecisionBasis 补记及外部资源缺失语义 | H |
| **横切合同** | ResearchSpace 身份/权限、统一事件与精确引用、W3C 映射、V1 只读迁移与未映射损失报告 | H/S/R |

后续优先完善 H/S/R 接口及不变量，按 **S1 → S2 → S4 → S3** 讨论语义；成熟后再考虑高级功能和实施计划。此顺序是**设计优先序**，不是运行时开发授权或各模块必须串行的实现依赖。

### 明确暂不冻结

- 核心对象与研究维度的 Schema 字段、强制覆盖范围、ContextProfile/World 等价判定算法；
- S1 中“语境改变后允许同 Assertion 新 Revision 还是强制新 Assertion”的机械准入规则；
- L2–L5 等级或偏序、通用证据充分性/概率模型、默认科学有效性评分；
- 多主体最终接纳政策、复杂论证计算、查询算法和数据库物化技术选型；
- 真实任务反馈、Agent 唤醒、正式实施 PR 的排期及 LIVE_* 授权。

## 8. 对后续设计和实施提案的要求

1. 任何新增核心机制须指出**主责 H/S/R**、保证范围、输入/输出引用和禁止跨越的职责边界；不能归入者优先作为扩展候选。
2. 设计评审应同时给出正例与负例：如迟到登记、未知语境、两主体相反评价、相同结果不同解释、外部原文件已丢失、关联边误晋升、被质疑前提的独立支持路径等。
3. 证明“机器能保持身份、版本、来源和边界”，不能冒充证明“机器知道科研结论是否真实”。
4. [PR #33 实施契约草案](V3_IMPLEMENTATION_CONTRACT-DRAFT.md) 的模块与 R1–R11 待裁事项应**依据本轮后续决策重新核对**；本文件不默示批准它、不启动 M1–M6、不改变当前 V1 冻结基线。
5. 本文为持续讨论的**候选基线**。任何实质性修改应留版本与决策记录；确认后另行决定如何形成正式 ADR/实施合同。
