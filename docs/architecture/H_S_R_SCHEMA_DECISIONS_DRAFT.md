# Schema 与接口层的决策、修订请求与验证边界

> **PR #47 · DRAFT-PROPOSAL · 2026-10-29。** 登记本层（编码与接口形态）的取舍、备选方案与后果，以及**需要回写 PR #42 契约层的修订请求**。本层不新增领域裁决；凡涉及领域语义的疑问一律进入 §3 的修订请求清单，不在本层私自定案。**Proposed，不表示已实施。**

## 1. 决策登记（SD-\*）

**登记纪律（防摘要漂移）**：本表与 §4 回归风险表的"决策"列只写**决定了什么**加上被引规则号，**不得复述规范参数**——键的组成、枚举取值、阈值与时长一律以被引条文为唯一真源。理由有实证：本轮 `SI-41` 把幂等键改为四元组并永久绑定之后，本表 `SD-14` 仍写着旧的二元组键与"窗口外重试产生新记录"，`§2.1` 请求表也仍与刚修的 `SI-16` 相冲——同一事实写在两处、修一处漏一处，本阶段这类缺陷出现了三次。摘要之所以躲得过检查，是因为它引用的是概念而非规则号，闭包检查看不见它。

| 编号 | 决策 | 被否决的备选与原因 | 后果与代价 |
| --- | --- | --- | --- |
| SD-01 | 规范形态取 **JSON-compatible 值模型**（HCF） | 直接以某序列化后端为准（protobuf/列存）——会把传输/存储选择上升为语义真源；RDF 三元组——丢失"字段/槽位"这一规范化检查的基本坐标 | 需要一次显式"规范字节形态"（SF-50）才能做逐字节比较；对性能敏感的读侧要靠投影层，不能改真源形态 |
| SD-02 | 规范键名**逐字等于领域阅读名** | 独立命名层 + 编译期映射（可读性更好，但映射表成为第二真源，且"规则 ↔ 字段"的机验链变长）；短键压缩（省字节，但每次读都要查表，且日志不可读） | 载荷比紧凑方案大；改名必须走 `name_map` 且要求双射（SRG-31） |
| SD-03 | 五态用**带标签值** `@st` | 稀疏 + sidecar 状态表（两处写，易漏写导致状态漂移，正是 UN-03 要防的）；哨兵值/保留字符串（污染取值域，UN-01 禁止空串当未知）；`null` 表未知（直接违规） | 载荷啰嗦；所有读写都要经过状态包裹器；模板与界面需要紧凑渲染层（属派生投影，不得回写真源） |
| SD-04 | 规范形态**槽位穷尽**，稀疏只在入口且只展开成 `ABSENT` | 稀疏为规范（省字节，但"未提交"与"未登记"不可区分，直接违反 UN-03 的可查询性要求） | 载荷更大；入口扩展器必须是全系统唯一一处，否则各处自行"补全"就成了 DF-08 的漏洞 |
| SD-05 | **禁止内容寻址身份** | 内容哈希当 ID（天然去重、传输省带宽）——但同内容即同 ID 等于**自动合并**，违反 ID-07（合并是登记行为）与 RV-05（同指称冲突不自动合并） | 重复内容需要显式合并登记；跨空间同步无法靠哈希比对；摘要仅用于载体校验与回放核验 |
| SD-06 | 引用是**受约束字符串** `obj@rN[#rep]`，角色由外层绑定对象承载 | 引用对象化 `{id, rev, role, kind}`（类型更严，但角色语义属于绑定关系而非引用本身，塞进引用会让同一引用在不同角色下产生不同字节，破坏 SF-31 比较与去重） | 引用形态校验靠 pattern；角色校验在绑定层（`RL1-02`） |
| SD-07 | HSR 记录的追加式存储由本层定义，**与 V1 历史事件面的合一暂不裁决** | 现在就并入 V1 事件流——事件族与信封是冻结面，且五类对象的追加语义与既有 20 个事件词汇并非一一对应，硬塞会迫使领域语义迁就事件名（DF-02 反向污染）；现在就新增事件族——是另一次冻结面变更，需独立评审与人工批准标记 | **在裁决前不得声称"HSR 记录已进入单一事件真源"**（SF-73）。两套追加记录并存期间**不存在共享序号轴**：V1 的 `eventSeq` 是 per-workstream 的事件日志序号，与 HSR 记录序无关（V1 自身也钉住 eventSeq 与 occurredAt 结构性无关）。因此跨平面连接**只允许** HSR 侧的显式 `external_citations[]`（SF-28、SD-20），且它是断言不是可解析引用 |
| SD-08 | **只存审计视图**，脱敏读取时现算 | 预存脱敏副本 / 物化脱敏视图（读放大小）——但会把"谁看不见什么"写进真源，且脱敏规则一改就得回填历史，正是 SP-10 禁止的事后抹除 | 高频读要重算；缓存必须按授权类分键（SI-34），实现有压力会持续诱惑工程侧偷工 → 已在负面清单钉住 |
| SD-09 | **领域定义保持 Concept 对象**，编码层词表只管形态枚举 | 关系类型/Scheme 降级为字符串码表（实现简单）——但它们需要来源、声明者、修订与被论证引用，降级会使它们脱离规范化检查与冲突登记（DF-02、DF-04） | 注册面继续增长；需要 §5 的预算纪律；SRG-02 的判据必须被校验器支持 |
| SD-10 | 数值以**十进制字符串**承载 | JSON number（省字节、可直接运算）——但浮点把 `1.20` 与 `1.2` 折叠，测量精度属于真值条件（PR-ID-4）；自定义原生数值类型（依赖后端支持） | 运算与比较下沉到实现层；Schema 层不能做数值校验（与 RPT-07 一致） |
| SD-11 | 并发前置失败码 `F-PRECONDITION-REVISION` **以修订请求提出**（§3 A-01），本层不扩 `F-*` 表 | 直接在本层加一个码（最快，但 `F-*` 词表的真源在契约层，私自扩表会让两份文档说两种话） | 契约层采纳前，实现只能退化到 `TOOL_INPUT + detail.precondition`，该退化必须有测试钉住（SI-24） |
| SD-12 | 新工具走 **`hsr_` 独立命名空间**，落地视为冻结面变更 | 复用/扩写既有 `research_fact_record` 等（省注册成本）——但会把 V1 语义（Fact/Claim）与五类对象混为一名，DF-04 的"不可替代"当场失效 | 宿主注册表里两套工具长期并存，Agent 需要明确用法边界（属实现期文档工作） |
| SD-13 | 本层工件**本轮不入 `schema/**`** | 直接提交 `schema/hsr/*.schema.json` 草案（看起来"更可执行"）——但会撞上冻结面 sha256 双向校验与 probe 投票，且未经人工批准行，构建会红 | 设计文档不可被机器加载；落地要多一次冻结变更流程（SF-71 已登记顺序） |
| SD-14 | 幂等键 = **四元组** `(actor_ref, space_id, operation, client_request_id)` + 首次请求体摘要（SI-41）；修订写入需 `expected_head_revision` | 服务端内容指纹去重（调用方省事）——但重试与"再次登记同一内容"不可区分，后者是合法行为（ID-07、RV-05） | 键对首次结果**永久绑定**，去重窗口只是缓存策略、超窗重放也不得产生新记录；调用方须实现请求 ID，确需重复登记必须换新 ID。（本条原文写的是二元组键与"窗口外重试产生新记录"，与本轮修完的 SI-41 冲突——同一事实写在决策登记表与接口基座两处，改一处必须回看另一处） |
| SD-15 | 分页游标**自包含知识截点** | 裸偏移/裸 seq（简单）——晚到登记会使翻页重复或漏项，"历史重建"不可复现（T-02） | 游标不可跨截点复用；长会话查询需重建 |
| SD-16 | 名称映射**默认同名、仅改名时登记** | 全量登记（映射表完整但噪音大，且会诱导"顺手加别名"） | 改名审计要靠增量登记纪律；别名禁止（SRG-31） |
| SD-17 | 工具名统一 `hsr_<主题>_<动词>`，动词取**闭合词表**，并禁止 `set`/`update`/`delete`/`remove`/`patch`/`mark`/`current`/`merge`/`sync`/`revert` 入名 | 自由命名（读起来自然）——但「amend/revise」这类词本身暗示就地覆盖，是领域明令禁止的行为在名字里的残留；名字一旦容许变异语义，实现与 Agent 都会朝那个方向漂 | 需要一次性重命名若干建议名（`_add → _register`、`hsr_view_state → hsr_state_axes_get`、`hsr_export_project → hsr_scope_export` 等）；`revise`/`amend`/`adopt` 保留，但由 ICX-05 用响应形态测试钉死「只追加不覆盖」 |
| SD-18 | 四个修订入口（IC-H2/S3/S5/A2）是**同一写原型的四个 profile**，共享一条代码路径，只在载荷校验分支分叉 | 四套独立实现（贴合四个 IC 条目）——四套实现必然漂移出四种拒绝行为与四种前置校验，正是本层要防的「两份文档两种话」 | 需要参数化测试资产：同一非法载荷 × 四入口必须同码同路径（SS-W-01） |
| SD-19 | 载荷表**不得重复信封槽位**（新增 SS-09） | 载荷自带 `recorded_at`/`registrant_ref`（自描述更方便）——同值两处写必生漂移，且脱敏时两处形态可能不一致 | 读者需知道信封字段才能读懂载荷；由形态校验兜底 |
| SD-20 | 跨平面引用只能在 **HSR 侧**登记（`external_citations[]`），V1 侧引用 HSR 标识本轮不做 | 双向可解析引用（对称、好用）——但 V1 事件 payload 全部 `additionalProperties:false`，塞进 HSR 标识就是冻结面变更；而让 HSR 侧引用可被"解析校验"又会把 V1 标识解析器变成 HSR 的隐式依赖（方向违规） | V1→HSR 方向在过渡期**不可达**（只能靠 HSR 侧记录被查询到）；导出与审计必须声明这一不对称（§5.1） |

## 2. 需要新增的机器兜底（本层能做的结构保障）

| 编号 | 兜底 | 保障的是 |
| --- | --- | --- |
| SD-G-01 | 记录与报告对象模型**封闭**（未知键即非法） | 无处塞 `confidence`/`score`/`is_current`（SF-N-02、RPT-04） |
| SD-G-02 | 呈现层专用取值放在与存储枚举分离的类型空间 + 写前校验 | `UNVERIFIABLE_REFERENCE`/`UNVERIFIABLE_TO_YOU`/`NOT_DISCLOSED` 不得落库（SCR-33、SCR-52） |
| SD-G-03 | 对象引用与 `rec:` 引用是不同类型 | H 记录不得充当论证端点（SF-24、RF-05） |
| SD-G-04 | 引用 pattern 强制带版本 | `latest`/无版本引用无法写入正式槽位（SF-23、DF-03） |
| SD-G-05 | 多值槽位禁止空集合表达未知 | 空数组不是"未知"（SF-14、UN-01） |
| SD-G-06 | `severity` 只能随 `FAIL`；两个需理由的 outcome 必带 reason | 判定线不被混用（RPT-00、SCR-10/11） |

## 4. 稳定性风险（会持续拉偏设计的力量）

| 编号 | 风险 | 表现 | 本层的对策 |
| --- | --- | --- | --- |
| SD-R-01 | **紧凑性压力**攻击五态与槽位穷尽 | "太啰嗦，用 null 吧"→ UN-01/UN-03 全线失守 | SD-03/SD-04 登记为决策；紧凑渲染只允许出现在派生投影 |
| SD-R-02 | **性能压力**攻击"只存审计视图" | 预存脱敏副本 → 谁看不见变成真源（SP-10） | SD-08 + 负面清单 + SCR-50；缓存只允许按授权类分键且可失效 |
| SD-R-03 | **注册面增长**侵蚀五类闭合 | 图省事把关系类型/Scheme 降级为码表（SD-09 被否的那条路） | SRG-02 判据 + 校验器支持 + 每轮复审专项核对 |
| SD-R-04 | **V1 与 HSR 双身份长期并存** | Agent 与用户混淆 `research_claim_record` 与 Proposition 登记 | SI-03 显式禁止自动同步；实现期需专门的用户文档与工具描述（不在本层范围） |
| SD-R-05 | **冻结面摩擦**导致绕过 | 为省流程把 HSR 字段塞进既有声明式记录或事件信封 | SF-72 命名空间分离；SI-02 明示流程；SD-G-03 类型隔离 |
| SD-R-06 | **数值字符串**使运算散落各处 | 各实现自行 `parseFloat` 比较，产生伪等价 | SD-10 + SF-40；本层明确不做数值等价判定 |
| SD-R-07 | **脱敏函数**被就地"优化"成查表短路 | 早退会改变可数的逻辑工作量，两世界由此可辨（SP-07） | SI-33 恒定响应面（① 键集 ② 量级 ③ 工作量计数器相等——早退必然改变计数，故可断言；不用墙上时钟） + 接口基座 §10 第 1 / 1a / 1b 条测试义务 |

## 5. 验证边界（诚实声明）

- 本层是**设计文档**：未编写或运行任何 Schema 文件、校验器、序列化实现、接口桩件或性能测试；未运行任何真实科研任务。
- 各文档"最小验证预期"是**测试义务清单**，不是已执行结果。
- 仓库门禁只覆盖静态一致性（链接、索引、归属、表格形状），**不验证领域语义或本层设计的可实现性**。

- **检查脚本自身会错，报红之前先验脚本**：验 `ICX-06` 时用 `re.search("ICX-06.*")` 取封闭清单，匹配到的却是**第一处提到** `ICX-06` 的表格行（某工具行的备注列），抓到空集并误报"等式不成立"；按行首 `| ICX-06 |` 锚定重跑后正常。同理，把某条性质写进"已真验"清单之前，必须先把它的判据在语料上跑通一次。

上述性质的复跑方法**就地给出**——本层只能改 `docs/architecture/**`，无权把检查提交进 `scripts/`，所以"可复跑"必须靠下面这段就地片段，而不是靠一个不在仓里的脚本：

```bash
cd docs/architecture && python3 - <<'PYCHK'
import io,re
docs=['H_S_R_SCHEMA_FOUNDATIONS_DRAFT.md','H_S_R_OBJECT_SCHEMA_DRAFT.md',
      'H_S_R_CHECK_SCHEMA_DRAFT.md','H_S_R_REGISTRY_SCHEMA_DRAFT.md',
      'H_S_R_INTERFACE_FOUNDATIONS_DRAFT.md','H_S_R_INTERFACE_CATALOG_DRAFT.md',
      'H_S_R_SCHEMA_DECISIONS_DRAFT.md']
ID=r'(?:SF|SS|SCR|SRG|SI|ICX|SD|T-GAP|A)-(?:N-)?\d+[a-z]?'
de=set(); rf=set()
for d in docs:
    t=io.open(d,encoding="utf-8").read()
    for line in t.split("\n"):
        if line.startswith("| "):
            c = line.split("|")[1].strip()
            if re.fullmatch(ID, c): de.add(c)
    rf.update(re.findall(ID, t))
print("定义", len(de), "引用", len(rf), "悬空", sorted(rf-de), "未引用", sorted(de-rf))
PYCHK
```

目录覆盖与工具名同理：对目录表按以 `| \`hsr_` 开头的行取工具，比对其中 `IC-[HSARP]\d+` 的映射集与契约 35 操作集（双向差集应为空），并断言未映射到 `IC-*` 的行恰为 `ICX-06` 那四个。

**这些数字是随文档变动的一次性快照**：改了规则编号或目录行必须重跑，否则本节就成了虚假声称——本节自身就是活例：该计数已因新增规则从 210 涨到 238、240、241（`SRG-24`、`SCR-77`、`A-11`），每次都靠重跑才没留下错数。- 上述性质**只证明本层自洽且忠实引用**，不证明设计可实现、不证明可实现语义正确，更不构成任何"已验证/已实现"状态声称。
- 本层依赖 PR #42 契约层，而 PR #42 本身仍是未合并的 Draft；本层与契约层的任何冲突都以契约层为准并触发 §3 修订请求。

## 5.1 两套追加记录并存期间的最小审计规则（过渡期，未裁决不等于不约束）

| 编号 | 规则 |
