# G1 可信部署 Profile 差异对账（T-SEC）

> 2026-11-03 · 授权与判据：`g1/G2-DEV-PLAN.md §0bis / T-SEC`（外部审查收口，现行）
> 性质：**甲类文书**（非 PoC、不做攻防实验；只改 `experiments/**` 与 G1 契约文档，不落生产代码/DDL/`schema/**`）
> 结论：两套 Profile 的差异**只落在安全部署的适用域**；五类对象、H/S/R 结构、历史语义、事件名封闭集**未动**。

## 1. 两个 Profile

| Profile | 威胁主体 | 强制面 |
|---|---|---|
| **P-T（可信首版，默认）** | 用户与**同进程 Plugin 可信**；不把「主动窥探其他 Space 的对抗性租户/恶意 Plugin」当威胁主体（§0bis 固定范围原文） | 正常授权、Space 隔离、数据不越界、WITHHELD/UNKNOWN 不得变成科学断言、普通越权拒绝、检查报告完整性 |
| **P-A（未来敌对部署，可选加固）** | 对抗性租户/恶意 Plugin、恶意枚举者 | 响应恒时（恒定三可观察量）、恶意枚举下的**逐字节同形**、隐含计数侧信道穷尽证明、缓存/CDN/日志按授权类分键的端到端证明 |

**分类规则**：只把「**需要对抗性执行环境或穷尽证明**才能成立」的判据降级为 P-A；把「**语义正确性、授权正确性、呈现不越界**」的判据保留为 P-T 强制。降级 ≠ 删除：原条款、夹具与判据全部保留，只是**退出首版放行门**，登记在 P-A 套件。

## 2. 逐项对账表

### 2.1 SP-07（存在性/侧信道不推断）

- **原条款**（#42 SP-07，经 `g1/G1-ADJUDICATION-TABLE.md:201` 引录逐字）：「对无权调用者，『不存在』与『无权可见』必须呈现为同一个不可区分结果」「两者的区分只存在于服务端授权判定、内部审计视图与有权审计日志中」「无权调用者**不得通过精确计数、错误码差异、响应时延、排序位置、缓存命中或总数减去可见数推断**」；`sanitize()` 把 `REF_UNRESOLVED` 与 `WITHHELD_REFERENCE` 合并为 `UNVERIFIABLE_REFERENCE`（RPT-09/RPT-10）。
- **分类**：**部分保留 / 部分降级**。
  - **P-T 保留**：① 拒绝码 + detail **形状**不得承载「存在且属他人」（`NAMESPACE_ESCAPE` 外发形态与不存在同形，D1-c/C1 裁决）；② `sanitize()` 合并两类不可用引用（RPT-09）；③ **不得发被屏蔽条目的精确计数/标识/时间分布**（SP-03 系），计数只进内部审计面；④ 有权主体计数如实；⑤ 审计面保留真因（SP-10 真源唯一）。
  - **P-A 降级**：**响应时延**恒时、**排序位置/缓存命中**的量化不可分辨、**总数减可见数**的穷尽证明、两世界**逐字节**同形。
- **用户裁决依据**：§0bis 固定范围「首版用户与同进程 Plugin 可信，不以主动窥探其他 Space 的对抗性租户/恶意 Plugin 为威胁主体」＋ T-SEC 条目「响应恒时、恶意枚举下的字节逐等、隐含计数侧信道穷尽证明……不作可信首版的单独放行门」。
- **实施 Profile**：P-T 由 PR-3（存在性呈现落码，`G1-READ-02`/E-01）与 PR-2（`sanitize` 封闭映射）实现；P-A 无实现卡，未来由安全加固立项。
- **正例**：有权主体读目标 ⇒ 正常载荷；无权主体读同一 oid ⇒ 与不存在**同码同 detail 形状同键集**（字段级），审计行可回看真因（现状证据：`tests/events-of-scope.test.ts:58`、`tests/p4-read-isolation.test.ts:94`）。
- **负例**：无权主体收到的响应键集中出现任何「存在/属他人」信号（含 `hiddenBy*` 计数、精确 total）⇒ P-T 即判红；P-A 追加：两世界逐字节等 + 时延同分布。
- **归属**：PR-3 卡主（机制落码）；P-A 加固归未来安全立项（不自动生效）。

### 2.2 RPT-09 / RPT-10（呈现不可用与不可区分）

- **原条款**（`g1/G1-ADJUDICATION-TABLE.md:254`）：RPT-09 `sanitize()` (a) 合并 `UNVERIFIABLE_REFERENCE` (b) `NOT_DISCLOSED` (c) 无计数 (d) 响应形态不随目标存在而变；RPT-10「呈现 `UNVERIFIABLE_TO_YOU` 而非 `ACHIEVED`/`NOT_ACHIEVED`」。
- **分类**：**保留**（(a)(b)(c) 与 RPT-10 全部是语义正确性）＋ (d) 的**对抗性穷尽形态**归 P-A。
- **用户裁决依据**：§0bis「不得将 WITHHELD 或 UNKNOWN 变成科学断言，必须保留」。
- **实施 Profile**：P-T（PR-2 呈现层 + PR-3 报告面）；(d) 的字段级同形属 P-T，逐字节归 P-A。
- **正例**：遮蔽/未解析引用在报告面呈现 `UNVERIFIABLE_TO_YOU`/`NOT_DISCLOSED`，且不出现 `ACHIEVED`/`NOT_ACHIEVED`（`tests/p4-read-isolation.test.ts:94`、prex 的 `WITHHELD-UNKNOWN` 负例）。
- **负例**：把 `WITHHELD` 渲染成 `NOT_ACHIEVED`，或以「不可用」为由给出否定结论 ⇒ 两 Profile 同判红（这是「不得变成科学断言」的硬核）。
- **归属**：PR-2 卡主。

### 2.3 SCR-54（两世界逐字节同形，常量 S 封闭形态）

- **原条款**（`g1/G1-ADJUDICATION-TABLE.md:332`）：SCR-54 两世界逐字节同形（常量 S 封闭形态）；此前作为 PR-3 退出门禁（`g1/G2-DEV-PLAN.md:346`「两世界逐字节同形探针（SCR-54 先例形态）exit 0」）。
- **分类**：**降级为 P-A**（逐字节/恒定形态属对抗性执行环境判据）。
- **用户裁决依据**：§0bis T-SEC「恶意枚举下的字节逐等……作为未来敌对部署 Profile 的可选加固，不作可信首版的单独放行门」。
- **实施 Profile**：P-A；P-T 保留其**字段级前身**（D1-c 的键集+码+detail 等值），该前身已在 `G1-READ-02`/D1-c 的正反例中。
- **正例**：P-A 下两世界（存在无权 vs 不存在）响应逐字节等、常量 S 封闭形态可复现。
- **负例**：P-T 首版**不**以该探针放行；若把该探针设为首版门，时延/序列化抖动会产生非确定红（判据不可复现），且它不是语义正确性证据。
- **归属**：探针与语料保留在 `attacks/` 与 G1 契约夹具表（T-P7/T-N11/MUT-5 形态），**不删**；启用条件 = P-A 立项。

### 2.4 G1-READ-02（E-01 呈现：refuse vs withhold）

- **原条款**（`G1-RECONCILIATION-CHECKLIST.yaml:213-222`）：`NAMESPACE_ESCAPE` 的拒绝本身声明「该 oid 存在且属他人」⇒ 与 D-12 叠加成存在性 oracle；需正面裁定；现状 = 显式拒读（`tests/events-of-scope.test.ts` 钉住）。
- **分类**：**保留**普通越权拒绝与检查报告完整性判据；**降级**其「两世界同形探针」的对抗性形态（见 2.3）。
- **用户裁决依据**：§0bis T-SEC「`G1-READ-02` 保留普通越权拒绝与检查报告完整性判据」。
- **实施 Profile**：P-T（PR-3 落码）；条目仍为 B 层 open 且有归属（实施工作不因分类而消失）。
- **正例**：无权主体越权读 ⇒ 拒绝（有码、有审计真因、无存在性判定）；检查报告可见性从被检对象派生、报告完整性可判（`tests/g5a-d24-read-attribution.test.ts`、`tests/events-of-scope.test.ts:58/65`）。
- **负例**：拒绝码/detail 出现「存在且属他人」的可区分信号；或报告面绕过授权直接可读 ⇒ P-T 判红。
- **归属**：ADJ C1/D1-c 行（判据）+ PR-3（实施）。

### 2.5 D1-c / D1-d（存在性同形与泄露面封闭集）

- **原条款**（`g1/G1-ADJUDICATION-TABLE.md:51-52`）：D1-c 采 #47 形态，「对无权与不存在**完全同形**（同码、同 detail、同键集、同计数缺席）」；D1-d 泄露面封闭集 = {计数、detail 载荷、水位数值、分页 total/exhausted、缓存键}，对被屏蔽项一律不发，`hiddenBy*` 只进内部审计面。
- **分类**：**保留**（两者都是语义/授权正确性）。
- **用户裁决依据**：§0bis「正常授权/Space 隔离/数据不越界……必须保留」＋ 固定范围的可信边界（不把「穷尽证明」当门）。
- **实施 Profile**：P-T。
- **正例**：隐藏 0/1/≥2 三态在普通调用者处**字段级**同形（键集、码、detail 形状、计数缺席）；有权调用方计数如实；审计面可回看计数。
- **负例**：`hiddenBy*` 键回到调用方 echo 面；或 `exhausted` 对可见集说谎 ⇒ 判红。（现状证据：`g1/G1-CONTRACT-EVENT-AUTHORITY.md` 新形态段；`tests/p4-read-isolation.test.ts:64/94/163`。）
- **归属**：PR-2（echo 键集拆两套）/ PR-3（落码）。

### 2.6 PR-3 / PR-9（实施卡验收项）

- **原条款**：PR-3 退出门禁含「两世界逐字节同形探针 exit 0」（`g1/G2-DEV-PLAN.md:346`）；PR-9 含「两世界同形探针」验收句。
- **分类**：**同步验收项**——探针从「首版退出门禁」移入「P-A 套件」；PR-3/PR-9 保留普通越权拒绝、报告完整性、正常隔离与「不得把 WITHHELD/UNKNOWN 变科学断言」的验收。
- **用户裁决依据**：§0bis T-SEC「同步 PR-3/PR-9 的验收项；不准仅删红测试」。
- **实施 Profile**：P-T 门禁 = 字段级同形 + 零 `hiddenBy*` + 审计回看；P-A 门禁 = 原探针 exit 0。
- **正例**：P-T 门禁在现有装置上可确定性复现（无时延依赖）；P-A 套件独立登记、独立启用。
- **负例**：把探针删掉且不登记 ⇒ 视为「仅删红测试」，判违规；把探针强留作首版门 ⇒ 判「把加固当放行门」，同样偏离 §0bis。
- **归属**：PR-3/PR-9 卡主（验收项改挂）；P-A 套件由未来安全立项维护。

## 4. 谁负责正式科研采纳授权

1. **正式科研采纳（首版）**：由**用户**授权——G1 冻结放行 + G2 乙类开工两道门（§0bis 固定收尾门禁 ③：技术 PASS/FAIL 只做自动分流，不构成冻结或上线许可）。
2. **P-T 敌对性豁免**：即本文件的分类结论，依据是用户经 §0bis 给定的固定范围（「首版用户与同进程 Plugin 可信」）。任何**收紧或放宽**该范围的改动须回到用户裁决，不由实现者自行扩写。
3. **P-A 加固启用**：由未来敌对部署立项的负责人（PR-3/PR-9 卡主 + `Frozen-Face-Review` 人工批准标记）提出并走契约修订程序；**不自动生效**，也不因本文件而视为已批准。
4. **事件名**：审批仍逐名办理（`Approved-By` 程序），本文件不新增、不改名、不废止任何事件名。
