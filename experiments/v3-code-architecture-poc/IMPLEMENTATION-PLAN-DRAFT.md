&nbsp;&nbsp;**a. `described_at`** —— 记录所描述的事件/状态**发生或适用**的时间。它是被描述世界的时间，**不得转换成 `CommitSequence`**（PoC 现状即犯此错：把它当排序键用）。
&nbsp;&nbsp;**b. `recorded_at`** —— 系统**实际登记**该记录的时间（墙钟）。
&nbsp;&nbsp;**c. `CommitSequence`** —— `ResearchSpace` 内的**事务提交顺序**，提供一致历史截点。
&nbsp;&nbsp;G1 要定义的是**外部 `recorded_as_of`（墙钟）如何确定性映射到 `CommitSequence`**，必须含两个分支的确定取值：**同一毫秒内多次提交**、以及**该时刻没有任何提交**（否则截点不确定 ⇒ 同一查询两次结果不同）。
&nbsp;&nbsp;并须明写：**PoC 目前把 `recordedAt` 与 `seq` 当同一数值的两个名字**（D-5，`READINESS.md:34`），正式契约**不应只在两个名字里二选一**，而要区分"登记时间"与"提交顺序"两个概念——改名前调用方清点仍要做，但那是迁移工务，不是语义裁定。**此项属接口修订，不触及顶层 H/S/R 架构**（H/S/R 职责划分不变，Kernel 仍不含科研语义判定）；④ **V1/V3 过渡期历史正源**（同一空间内 v2/v3 事件混存时谁是权威；与 D-11 `ledger.contract_version` 版本记录方式同批定，`READINESS.md:105`）；⑤ D-12 / E-01 的存在性 oracle 裁定（§10）；⑥ 若生产形态要求硬隔离，此处一并裁定 symbol 通道是否重做（`ASSESSMENT.md` §9.1 第 1 条） |
