## 2. 记法与命名纪律

| 编号 | 约定 |
| --- | --- |
| N-01 | 文中字段名（如 `recorded_at`）是**领域阅读名**，不是冻结的 Schema 键名、数据库列名或类型字段。落地命名由后续 Schema 设计决定，但必须能无损表达本文与对象契约声明的语义角色。 |
| N-02 | 枚举值写作 `UPPER_SNAKE`。枚举是**领域取值集合**；除明确标注“封闭”者外均为**开放注册**，可由后续版本增加而不构成语义破坏。 |
| N-03 | 不带系统前缀的 `L0`/`L1` 是**歧义写法**（旧文档中它曾指统一形式化轴），本层文档内禁止使用。一律写作 `S-L0`、`S-L1`、`R-L0`、`R-L1`；表格列名同样写全，不写简并的“L0/L1 要求”。 |
| N-04 | 关系名（如“上游”“支持”）是阅读别名。含义与 W3C 精确等价时直接用标准名（`prov:wasDerivedFrom`、`skos:closeMatch`、`sosa:Observation`），不等价时保留领域名；内部五类分类不改写标准语义。 |
| N-05 | “登记”“使用”“支持”“接纳”“为真”是五个不同动词，禁止在字段说明或操作中互相替换（继承主基线 §1 与 C01/C02）。 |
| N-06 | 关系/引用一律写成 `源对象 —〔角色〕→ 目标对象@精确版本` 的方向形式；逆向查询由检索提供，不意味着反向关系存在。 |

## 3. 对象身份与归属

| 编号 | 规则 |
| --- | --- |
| ID-01 | 每个正式对象有全局唯一 `object_id`，永不复用、永不重新解释。`object_kind ∈ {ENTITY, CONCEPT, ASSOCIATION, ARGUMENTATION, PROPOSITION}` 在创建时固定且**永不可变**；改变“kind”意味着登记另一个对象。 |
| ID-02 | 每个对象归属唯一 `space_id`（ResearchSpace），创建时固定且不可变。不存在跨空间迁移，也不存在“共享实体副本”。 |
| ID-03 | 每次修订产生新的 `revision_id`，形成同一对象内的追加式线性序列。旧修订永不改写、永不删除。 |
| ID-04 | **精确引用** `object_id@revision_id` 一旦写入某记录，永不被后续修订重新解析或漂移（继承 X3、不变量 2）。 |
| ID-05 | **逻辑引用**（只写 `object_id`）只允许出现在明确声明“跟随当前”的非规范性位置：目录浏览、界面导航、用户手工选择的当前值。**禁止**出现在论证输入、结论、评价、接纳、检查结果或任何正式声明中。 |
| ID-06 | `AssertionID` 是 H 拥有的历史连续性链：成员是有序 `revision_id` 列表，每个成员可指向不同的 `PropositionID@revision_id`。链本身不携带含义、不携带真值、不是第六类对象。 |
| ID-07 | 对象身份不因两个登记内容“看起来相同”而合并。合并（判定同一对象、同一命题、同一概念）永远是**登记行为**：由主体显式声明并留下来源，见 `IDENTITY_CONFLICT`/等价候选机制。 |
| ID-08 | 未被对象化的记录（H 事件、来源引用、检查报告、快照、采用记录）有各自的记录标识，可被引用但不获得对象身份，避免为每条记录递归造对象。 |

## 4. 字段存在状态（五态）与“不虚构”原则

每个语义字段在任一修订中处于且仅处于下列一种状态：

| 状态 | 含义 | 允许出现在必填字段 |
| --- | --- | --- |
| `DECLARED(v)` | 已声明值 | 是 |
| `UNKNOWN(reason)` | 显式声明“当前未知/尚未确定”。`reason ∈ {NOT_YET_DETERMINED, INDETERMINATE_AT_SOURCE, NOT_RECORDED_IN_SOURCE, AMBIGUOUS_IN_SOURCE, UNRETRIEVABLE}` | 是（显式未知是合法登记） |
| `NOT_APPLICABLE(reason)` | 该角色对此对象不适用（例如无 World 限定的纯语法概念） | 是，须带 `reason` |
| `UNRESOLVED(ref)` | 引用已给出但目标不存在、不可访问或被空间过滤；引用内容原样保留 | 是，但记录为待解析 |
| `ABSENT` | 字段根本未提交，且不宣称任何信息状态 | 必填字段：规范化失败；可选字段：合法 |

| 编号 | 不变量 |
| --- | --- |
| UN-01 | `UNKNOWN` 不是否定、不是空串、不是 0、不是默认值、不是“不适用”。任何检查、查询、导出、摘要都不得把 `UNKNOWN` 呈现或转换为 `FALSE`、`REFUTED` 或“无相关记录”。 |
| UN-02 | 规范化、导入、导出、模板套用**都没有补全路径**：不得用默认值、词典最优候选或相似度推断填充 `ABSENT`/`UNKNOWN`。补全只能来自新的显式登记（新修订）。 |
| UN-03 | `ABSENT` 与 `UNKNOWN` 的差别必须可查询：前者是“登记者未说明”，后者是“登记者说明了不知道”。二者都不表示科学否定。 |
| UN-04 | `UNRESOLVED` 引用保留原样并进入可查询的悬挂引用集合；它不阻断对象保存，也不使依赖它的结论自动为假（缺失≠反证）。 |
| UN-05 | 因权限或跨空间过滤而不可见的记录，其呈现是 `WITHHELD`，与 `ABSENT`、`UNKNOWN`、`UNRESOLVED` 互不相同；不得把 `WITHHELD` 报告为“不存在”。 |

## 5. 时间语义（四类，互不替换）

| 名 | 语义 | 主责 | 典型混淆后果 |
| --- | --- | --- | --- |
| `recorded_at` | 系统登记时间 | H | 当成“事实发生时间” → 补录被当作当时已知 |
| `claimed_time` | 记录声称的对象层面发生时间 | 记录内容 | 当成登记时间 → 迟到登记被当作新发生 |
| `described_interval` | 记录所描述的适用范围时间/区间（如“该布局在 T1–T2 期间成立”），可 `UNKNOWN` 或开区间 | 记录内容 | 当成“永久有效”或“latest-write-wins” |
| `adoption_at` / `adoption_scope` | 某主体在某范围本次采用该记录的时间与范围 | 独立的采用记录 | 当成“记录被验证为真” |

| 编号 | 不变量 |
| --- | --- |
| T-01 | 四个值可两两不同且都需保留。任何“当前状态”查询必须声明使用哪一类时间以及历史截点（`as_of`），否则该查询视为未定义。 |
| T-02 | 晚到登记：`claimed_time = T1`、`recorded_at = T3` 的记录，在 `as_of = T2` 的“当时已知”视图中**不得**出现为已知；在 `as_of = T3` 视图中出现并标注为补录。 |
| T-03 | 不同来源的时间先后不构成物理或推理因果；排序需要相应论证与依据。 |
| T-04 | 结果时间、现象时间、分析时间与采用时间是四个不同问题；只在语义适用时对齐 W3C 名称（如 SOSA 的 phenomenonTime/resultTime），不因此把系统登记时间塞进标准字段。 |

## 6. 正交状态轴（互不可推导）

每条轴独立记录、独立可查询、独立可并存。任何轴的值都不得由另一轴推导，也不得由“缺失”推导。

| 轴 | 取值（开放/封闭见注） | 适用范围 | 不得推导 |
| --- | --- | --- | --- |
| A1 构造 | `DRAFT / SUBMITTED / CLOSED_DRAFT` | 仅 Argumentation | 证据强弱、结局、S-L/R-L 等级 |
| A2 规范化 | `S-L0`、`S-L1`（+ Argumentation 另有 `R-L0`、`R-L1`），由检查报告给出 | 全部对象 | 正确性、被接纳、被确认 |
| A3 解释确认 | `UNCONFIRMED / CONFIRMED(actor,at) / DISPUTED(actor,at)` | 全部对象，尤其 Proposition | 机器 S-L1 通过与否 |
| A4 研究结局 | `NONE_YET / SUPPORT / REBUT / UNDERCUT / INCONCLUSIVE / APPLICABILITY_FAILURE` | Argumentation | 命题全局真值、Draft 状态 |
| A5 本次适用 | `CONFIRMED / CONTESTED / UNKNOWN` + 适用 scope | 任一记录在“本次使用”中 | 原记录全局有效或永久无效 |
| A6 主体评价 | 多个并存评价（Proposition 子型） | 命题、论证 | 正式接纳、他人意见 |
| A7 正式接纳 | `NONE / ACCEPTED / SUSPENDED / WITHDRAWN`（派生投影） | 按主体、scope、精确命题版本、时间 | 命题真假、机器检查 |
| A8 资源可用 | `UNKNOWN / VERIFIED_PRESENT / UNRETRIEVABLE / HASH_MISMATCH / DELETED` | 有载体的 Entity | 内容曾不存在、结论为假 |

| 编号 | 规则 |
| --- | --- |
| AX-01 | 上表八条轴是**记录与投影层**概念，不是八种字段命名，也不是对象类别；实现可把它们组织为事件、关系或视图，但必须保持“不可互推”与“可独立查询”。 |
| AX-02 | 任何聚合视图（摘要、看板、Agent 上下文、导出 Profile）若省略某轴的已知值，必须显式标注“本视图未包含 X 轴”，不得让缺省值替该轴赋值。 |
| AX-03 | “未出现在本视图/查询结果中”属于呈现边界，不是一种状态；它不产生任何新状态值。 |

## 7. 引用类别（四型，禁止互相替代）

| 类别 | 语义 | 可用于 | 禁止读作 |
| --- | --- | --- | --- |
| `SEMANTIC` | 引用某对象的精确语义版本以表达含义 | 命题提及概念/个体/其他命题 | 该对象存在、该含义正确 |
| `PROVENANCE` | 来源、生成、派生（PROV 语义） | 记录生产链、文件来源 | 逻辑蕴涵、科学支持 |
| `INFERENTIAL` | 论证输入的角色绑定 | Argumentation 输入端 | 数据来源即前提、前提即真 |
| `EVALUATIVE` | 评价/接纳指向的精确目标 | Assessment、FactDesignation | 目标真假、他人态度 |

| 编号 | 规则 |
| --- | --- |
| RF-01 | 一个引用记录必须能说明其类别；同一记录同时具有来源与推理意义时，登记为**两条**不同类别的引用，不得混成一条含糊的“相关”。 |
| RF-02 | 正式声明（论证输入/结论/条件、评价目标、接纳目标、检查结果对象）必须使用 `SEMANTIC`/`INFERENTIAL`/`EVALUATIVE` 精确引用；ID-05 的“跟随当前”不适用。 |
| RF-03 | 引用一个对象不等于引用它的全部关联。任何“展开引用”“补充上下文”都必须逐条保留原引用与来源，并标注其为派生补充。 |
| RF-04 | 引用不存在的目标：保留为 `UNRESOLVED` 并报告，不静默丢弃；跨空间或权限不可见：报告为 `WITHHELD` 且不泄漏目标存在性。 |
| RF-05 | 未被对象化的记录（§ID-08）**可以**作为 `PROVENANCE` 来源、检查对象标注与高阶命题的讨论目标被引用，但**不能**充当 Association 的参与端点或论证的输入角色端点。需要“关于某次登记/检查本身的论点”时，登记为讨论该记录的高阶 Proposition，或由相应记录承担来源，不把记录升格为关系端点。 |

## 8. 修订与新建的通用判据

**G-REV**：把字段由 `ABSENT`/`UNKNOWN` 补全为声明值，或补充说明性内容 → **同一对象的新修订**；改变该对象的**身份构成字段**中已声明的值 → **新建对象**并保留旧对象，两者之间登记显式关系（不得用修订关系冒充替代）。其余字段变化 → 新修订。

各对象的**身份构成字段集合**在其对象契约的“身份与修订判据”一节各自列出一张表（Entity、Concept、Association、Argumentation、Proposition 契约的同名节）。通用边界规则：

| 编号 | 规则 |
| --- | --- |
| RV-01 | 身份构成字段的 `UNKNOWN → DECLARED` 补全永远是修订，不要求新建对象（否则无法渐进规范化）。 |
| RV-02 | 新建替代对象时，旧对象必须原样保留并可回放；替代关系是有来源的记录（属于 Association 或 H 记录），不是对象的隐藏属性。 |
| RV-03 | 修订不得改写历史检查报告、历史评价或历史接纳：它们锚定旧修订，新修订的检查是**新报告**（C11）。 |
| RV-04 | “同一对象的两个修订”与“两个对象”的判定错误会污染历史，因此每条对象契约都必须给出可判定的判据与至少一个边界反例。 |
| RV-05 | 同指称冲突（两个对象疑似同一或同一名称指向两个对象）不自动合并：登记为 `IDENTITY_CONFLICT` 关系记录，由主体裁决并留下依据。 |

## 9. ResearchSpace 与隔离

| 编号 | 规则 |
| --- | --- |
| SP-01 | 全路径（读、写、导出、图遍历、检索、摘要、缓存）必须做空间授权过滤；公共概念词汇的共享不赋予读取其他空间 Entity/Association/Argumentation/Proposition 的任何权限。 |
| SP-02 | 指向不可见空间的引用统一呈现为 `WITHHELD`：不报告目标内容、不报告目标存在性、不报告其空间标识。 |
| SP-03 | 因过滤而得到的**部分结果**必须携带边界标注（过滤原因、被屏蔽范围的存在性未知），使“没展示”不被读成“不存在”（C12、CS-24）。 |
| SP-04 | 跨空间引用无法解析时按 `UNRESOLVED` 处理；系统不得为了“方便”提供只读穿透视图。 |
| SP-05 | **跨空间复用只能靠显式导出/导入**：导入在目标空间创建新对象（`voice = IMPORTED`，来源引用指向目标空间内保存的导出工件），并逐条报告丢失的上下文。不存在“活着的跨空间引用”，也不存在共享同一 `object_id` 的两个空间视图。 |
| SP-06 | 主体身份按空间登记：同一自然人在两个空间是两个不同个体记录。接纳投影（A7）与归因查询因此**只在单空间内有意义**；系统不提供跨空间“某人总共接纳了什么”的聚合，这是隔离的既定后果，不是待修缺陷。 |

## 10. 通用不变量 DF-01…（细化层可引用，不得弱化）

| 编号 | 不变量 | 上游依据 |

| DF-05 | 未知、缺失、断链、截断、超时、不可访问与科学否定互不转换。 | C12、UN-01 |

| DF-07 | 规范化检查（S-L0/S-L1、R-L0/R-L1）是结构门禁，不判定科学正确性，也不阻断保存与继续研究。 | 主基线 §2、D17 |
| DF-08 | 规范化永不补全语义；系统永不虚构值、来源、时间或解释。 | UN-02 |
| DF-09 | 跨空间隔离不可通过词汇、导出、检索或引用穿透。 | 不变量 4、SP-01 |
