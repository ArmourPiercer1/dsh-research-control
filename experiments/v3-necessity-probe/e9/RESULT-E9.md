## 2. 抓到一个此前任何档位/指标都没覆盖的失败模式

> **检索失败不表现为"判错"，表现为"用邻近项目的数值搭出一个看似定量的修正"。**
> 记作 **伪造的定量性**（false precision）。

它为什么难防：
- **检测率看不见**——两臂判定相同，A/B 都是 1/1。
- **引用计数不仅看不见，还会奖励它**——差索引臂大量引用记录 id（`d06`/`d10`/`d09`/`d01`），
  在我上一轮那个"引证据量"打分器上会得**高分**。
  → **我此前把"引用记录条数"当正向指标是错的，现予撤回**：两臂本来就同分（10.5 vs 10.2），
    而 E9 显示**引用得多恰恰可以是串案的症状**。
- **一句散文警告挡不住**——两臂提示词里都写了
  「库里多台仪器都报 pi-mm…**不要把别的项目的数当成本项目的依据**」，差索引臂仍然全借，
  而且还写了「b09 属 B 项目仅作旁证」这种**半自觉**的免责话。
  → **散文级提示不是控制**（n=1，但方向明确）。

## 3. 由此得到**第一条正向的、可机验的设计要求**（本轮唯一）

审计链必须检查的不只是"这个数有没有出处"，而是
**"这个数的出处记录，其项目 / run / 工况 / 适用域，是否与论断的适用范围一致"**。
记作 **适用范围一致性谓词**（scope-match predicate）。

它恰好落在两条已有结论的交点上：
- E7/E8：**可发现性**（找不到本项目的证据，就去借别案的）；
- E8-R4：**数值必须与工况/适用域同生共死**（搬运时例外记录不跟着走——被借的 12.4% 在它自己家里已被判"约 3.1% 属数值容差"）。

**可机验的前提是结论侧格式**：只有当每条数值都带 `(值, 记录 id)` 对时，scope-match 才能自动跑。
→ 这**反过来给"写时义务"提供了一个比"帮人想清楚"硬得多的理由：它不是为了帮思考，是为了让这个谓词能跑。**
成本也具体：每条结论 1 行；收益是拦下一种**看起来最像合格工作**的失效。
