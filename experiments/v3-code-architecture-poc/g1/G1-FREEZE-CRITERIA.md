## 1. 为什么要分两层（单层判据的两个失效形态，都被点名过）

单层判据 = 「清单不清零就休谈冻结」。它同时在两端失效：

- **过松的一端（提前实现换绿灯）**：为了让 `--require-clear` 变绿，把只有落码才能关闭的条目
  （强制门、DDL、触发器摘要外置、计数器持久化）在冻结**之前**先做掉。这正面违反
  `IMPLEMENTATION-PLAN-DRAFT.md §2-G1`「未完成时禁止启动」——**G2 的真实 DDL、`capability_route` 演进、
  Schema 迁移器**恰恰是这条禁止的对象；把它们提前，等于用「基于错误的时间/所有权模型固化」去换一次绿。
- **过紧的一端（冻结永不可达）**：把 G3 的科研领域正反例、真库故障注入、`attacks/**` 迁入正式测试面、
  夹具世界迁移这些**验收义务**也算进冻结阻塞。这些义务的完成前提就是 G2 代码存在，于是「冻结」在定义上
  不可能到达，判据退化成装饰，最终仍然会被绕过（第七、八轮已实测过两次绕过：`G0-R-CLOSURE.md §6`）。

分层的实质不是放松门禁，而是**把「必须闭合」的判据范围说清楚**：合同判据闭合了才谈冻结；实施义务按 PR 交付。

## 3. B 层 —— 纯 G2/G3 实施与验证义务

**定义**：裁定与判据文本**都已在位文书中闭合**，剩余义务**只有**代码、DDL、迁移工务、夹具真库化、
故障注入、面锚重跑、验收测试。B 层条目**不计入冻结阻塞**。

**三条硬约束（缺一条就不是合法的 B 层条目，评审按洗白处理）**：

1. **有交付 PR**：写明由哪个 PR 交付（对拍《G2-DEV-PLAN.md》§2 的 PR 卡）。
2. **有责任者**：清单 `owner` 非空且非 `UNASSIGNED`（机器面在 `--require-clear` 拦；`owner` 的**权威性**
   ——Q 编号 / 裁定提交 / 用户指令三源之一——仍是人工判据，不许读成已机验）。本席位**不代填** owner：
   权威归属是指名动作，由条目责任者或用户执行；因此当前 B 层条目多数仍是 `UNASSIGNED`，
   `--require-clear` 照此判红，这是**正确的红**。
3. **有退出门禁**：写成可复跑命令 + 期望退出码（无 CI，见矩阵 §6.4）。

**「不计入冻结阻塞」的两条反向纪律**：

- **不得为了清单清零而提前做 B 层实现**。B 层的存在意义就是「这些活儿在冻结之后干」；提前做 = 回到 §1
  过松的一端，直接违 `§2-G1`。清单上 B 层条目在冻结时**允许是 `open`**，只要它有归属。
- **B 层不是垃圾桶**。凡「代码写出来才知道判据对不对」的条目（绑定约束、恒空视图语义、写面权威形状）
  一律属 A——判据本身未闭合，不能被实施义务吸收。

## 4. 分层怎么标（机器面 + 人工面）

- **YAML 字段**：每条条目加 `freeze_tier: "A"` 或 `"B"`（闭集取值；字段名/取值先改校验器再进清单，
  与既有「新字段先改校验器」纪律同序）。
- **缺字段 = 红**（`FREEZE-TIER`）：不给「缺省算 A 还是 B」留余地——缺省语义就是洗白通道。
- **取值漂移 = 红**：`freeze_tier: "C"` 之类一律 `FREEZE-TIER` 红（自验 M28）。
- **B 层必须带 `tier_basis`**（`FREEZE-TIER-BASIS`）：写明「依据哪份在位裁定/契约条文，本条的判据已闭合、
  剩余只有实施」，且必须含**可定位锚点**并通过与 `DONE-EVIDENCE` 同判据的**锚点真值**校验（假提交号 /
  幽灵路径红）。理由：B 层免检，所以降级必须留痕；降级到 B 是**判据面变更**，与替代关系同级。
  A 层条目不要求 `tier_basis`（从严方向不需要理由）。
- **歧义一律从严归 A**。分层有疑 ⇒ A，且不允许用「先标 B、以后补依据」的形态过关。
- **A 层非空是放行条件**：A 层条目数为 0（分层被整体抽空）⇒ `--require-clear` 判红。

```sh
node experiments/v3-code-architecture-poc/g1-checklist-validate.mjs              # 日常门：exit 0（分层字段本身红不红，与 A/B 是否闭合无关）
node experiments/v3-code-architecture-poc/g1-checklist-validate.mjs --self-test  # 变异自验：exit 0（条数一律以运行输出为准，含分层族新条）
node experiments/v3-code-architecture-poc/g1-checklist-validate.mjs --require-clear  # 终局门：当前 exit 1（NO-GO 期预期红）
```

**日常门行为一字不改**：`违规==0` 即绿；A/B 只作为统计维度打印，不参与日常红绿。

**终局门（`--require-clear`）谓词**：

```
违规 == 0
∧ A 层非空（tierA.items > 0）
∧ A 层 open == 0 且 A 层 assigned == 0
∧ 全局 unassigned == 0        ← 覆盖「B 层必须有归属」，且保留 A 层的纵深（旧项一字不动）
∧ 全局 superseded 未经人工确认 == 0（旧项一字不动）
```

被**移除**的只有一项：**B 层的 `open`/`assigned` 不再单独构成终局阻塞**（旧谓词里的全局 `open==0`/`assigned==0`
收窄为 A 层口径）。`--max-open <N>` 的进度护栏语义不变（仍数全局 open）。

**分层计数行**（新增，原「计数 items=… open=…」行逐字保留；下面就是 2026-11-01 本席位的**实测输出**）：

```
分层 A：items=20 open=16 assigned=0 done=4 superseded=0 superseded_unreviewed=0 ｜ B：items=7 open=7 assigned=0 done=0 superseded=0 unowned=6
```

**新增变异族（常驻，与判据同生死；本轮共五条，自验运行输出实测 31/31 全捕获）**：
`M27` 层级字段缺失红、`M28` 层级取值漂移红、`M29` **「A 层全量降级为 B 层且不补依据」的降级洗白红**、
`M30` **谓词型**——全量降级 + 每条补真实在盘的 `tier_basis` + owner 全部伪装成有主（违规面全过、
unassigned 归零）仍必须因「A 层被抽空」判红、`M31` 正向防死闸
「A 层全闭 + B 层仍 open 但有归属 ⇒ 终局门必须判绿」。**没有正向条的分层判据是死闸**——
「永远红」与「永远绿」是同一种失效（校验器头注原话）。

## 7. 诚实边界（机验拦得住什么，拦不住什么）

- 机验**拦得住**：缺层级、层级取值漂移、A 层被抽空、A 层未闭合、B 层无归属、`tier_basis` 假锚（提交号/路径
  不存在）、以及「全部降级成 B 且不补依据」这一条最省事的洗白路径。
- 机验**拦不住**：① 一条**真属于 A** 的条目被**带着真锚点**降级到 B（锚点真实 ≠ 结论支持）；
  ② `owner` 填了名字但填的是无权威来源的名字（`owner` 的权威性人工判据，清单头注原句）；
  ③ 本轮四专题是否真的都有文书（专题编号以各专题席位文书自述为准，本文件只登记实测在盘者）。
  这三面一律由**非作者审查者**在冻结申请时逐条核对，核对面 = 本文件 §5 表 + 各条 `tier_basis`。
- 本文件自身的变更纪律：改分层 = 改判据 ⇒ 与替代关系同级，需**非作者**具名确认；
  只许「B 升 A」（从严方向）与「依据补全」，「A 降 B」必须同批改 `tier_basis` 并在评审里点名。
