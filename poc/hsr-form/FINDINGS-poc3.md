# PoC-3 发现（检查归约 / 摘要域 / 两世界差分 / 幂等分页）

`node --test poc/hsr-form/poc3-check.poc.mjs` → **10 passed / 0 failed**。
但**绿灯不等于无缺口**：下面 5 条是实现时必然要替文档做的决定，其中 3 条我在写断言时发现**自己的断言抓不住它声称要抓的错误**，一并如实记。

| # | 规则 | 缺什么 | 两种合法实现各自会长成什么样 |
| --- | --- | --- | --- |
| G-1 | `SS-56` × `RPT-02` | 归约函数**无法区分"该层没有结果"与"该层全部通过"**：`reduceLevel([])` 返回 `ACHIEVED`。文档说候选载荷"不获得正式层级结果"，却没说这种**缺席**在报告里长什么样 | ① 该层级整体不出现在报告里 → "没有该层结果"与"报告漏算该层"不可区分，而后者是必须报警的实现缺陷；② 引入 `NOT_EVALUATED` 类取值 → 新增枚举，且必须说明它不参与 `RPT-02` 优先序，否则又回到归约歧义。**需要一句裁决** |
| G-2 | `SCR-57` × `SI-33` | `S` 常量只规定了**无可见权者**的情形；"有部分可见权、两世界隐藏集不同而可见集相同"是否也要求逐字节等价，文档未写 | ① 只对无可见权者要求常量 → 部分可见授权类下，隐藏集大小可通过分页边界、聚合计数等泄漏，`SI-33` 的恒定面只剩最弱一档；② 对所有授权类要求"可见集相同 ⇒ 输出相同" → 必须禁止任何按隐藏集基数计算的字段（我按②编码）。**需要一句裁决** |
| G-3 | `SCR-57` golden 形态 | 我的反向断言（把 `limit_applied` 钉成缺省常量应判红）在**单页长**下抓不住该错误实现：它只在被测页长恰好等于缺省值时才暴露。这正是 §10-6b 要求"页长 ≠ 缺省、两个页长各跑一次"的原因，但**golden 若按操作只存一份，双页长断言就无处比对** | ① golden 按 `(操作, 生效页长)` 逐份生成（已写进 SCR-57，但没说**页长取值集合**——穷举会爆，取样又留下漏检区间）；② 只存若干代表页长 → 必须声明"其余页长由参数化推导"，否则实现者不知道该测哪些。**取值集合是测试资产问题，仍需登记** |
| G-4 | `SF-52a` | 正向验证成立：排除集**不含自身**时，写入摘要 → 重算必得不一致（P3-3 的红路径可复现）。但文档没写**校验失败时怎么报**：重算不一致是 `HASH_MISMATCH` 型 `FAIL`，还是报告不可信降级 | 两种都属于检查层现有码能表达的，但语义不同：前者主张"内容被改过"，后者主张"我无法核验"。混用会伪造审计结论 |
| G-5 | `SI-41` | 幂等标记在响应里的**位置与优先级**未规定。我写桩件时先写成 `{ replayed: true, ...storedResponse }`，被存储响应的字段静默盖回 `false`——**一个合规实现可以完全一样地犯这个错** | ① 标记在信封（与响应体分离，永不覆盖）；② 标记在响应体内 → 必须规定合并顺序。文档两侧都没说，属于"看起来微不足道、实际会写歪"的那类 |

## 我确认无误的部分

`RPT-02` 优先序、摘要排除集的自引用不可实现性、`limit_applied` 与 `exhausted` 分属请求函数与可见集函数（两世界同请求必同输出）、`boundary` 恒定在场且不是五态值（`SS-15a`）、超限页长拒绝而非静默夹取——这些都能用可执行断言钉住，且反向断言（错误实现必红）除 G-3 外都成立。
