**这是对召回成功做过条件筛选的样本**，不能用来估计"召回失败率"。反过来，席位另计的 2 条**未闭合**

才是"根本没记下来"的形态——它们**没有修正后信念**，所以不进分母。两类必须分开报，混在一起就会得出

## 3. 真正缺的机制：不是"图遍历"，是"声明与工件的机验对账"

按席位给出的"检测需要什么能力"逐条归并（**这一步是我的推断**）：

| 事件 | 需要的机制 | 是否可机验（推断） |
|---|---|---|
| E-B1 v1 宽度统计撤回 | 冻结口径 `width_formulas`（ddof=0 / 索引差分位）已登记，v1 脚本违反它 | **可机验**：脚本常量与统计式 ↔ 登记定义对账 |
| E-B2 HEADLINE 混用群体口径 | 同名「SC 响应 yσ」两群体口径差 0.34 pp，headline 数 ↔ 64 行冻结表可对账 | **可机验**：headline ↔ 表行 join |
| E-B3 把零误差担保归于**不存在的 assert** | 脚注写 "unpaired -> abort"，但 `grep assert` 只有否定表述，manifest 自记 "no axial-symmetry assertion" | **可机验**：文本声称的担保 ↔ 代码内容 |
| E-R3 自述输出路径 ≠ 实际位置；清单只覆盖 6/13 文件 | 工件自述 ↔ 实际目录/清单覆盖度 | **可机验** |
| E-A3 取斑网格 10 µm → 1 µm（束斑 347→263 nm） | 口径登记 + deck `screen("wcs")` 步长的输入指纹 | **可机验**（前提是 deck 还在库；本案主要工件已不在库） |
| E-A2 中途快照被当作 run 终态 | run 终态登记 + 按 run 时间轴 join | **可机验** |
| E-A1 「结构性 4× 领先」实为种子继承 | 受控设计登记 + **汇总断言 ↔ 原始记录**语义核对 | 半机验（需语义判定） |
| E-R2 「独立能区」其实参考能量相同 | 构造法登记 + 版本间定义 diff | 半机验 |
| E-R1 RF 角色前提整体更换 | 模型边界自述 ↔ 结论的前提绑定 | 需人/语义召回 |

**结论（推断）**：真实修正里**约 6/9 的判别线索是"某条声明的前提/口径/担保，与工件内容不一致"**，
这类判定**不需要图遍历、不需要多跳召回**，需要的是两样便宜东西：
①**口径与前提登记表**（谁、什么定义、绑定到哪个工件指纹）；②**声明↔工件的确定性对账器**。
只有 3/9 真正需要"把旧前提拉回当前视野"的召回能力。

## 4-bis · 判读边界修正（2026-11-01，用户指令记入）

**本节作废 §4 原先最后一条 bullet 与 §1 表格"读法"段落的推论力度。** 原文写成
「双图谱、五类对象、内核与插件框架在 9 件真实修正里没有一件需要」——**这是过头话，撤回。**

撤回理由（用户裁定）：**V3 的对象是"今后如何逐步建立起干净的科研工作区，并保证结果可信、可审计"，
不是"如何清理并重建一个此前混乱的工作区"。** 用没有记录纪律时留下的资产去评价为建立记录纪律而设计的机制，
方向不成立，理由有两条，第二条是本判读原先没算进去的：

1. **样本性质不匹配**：9 件事件是"无纪律条件下产生、且事后被成功纠正"的遗留事件；
   前瞻性系统对其中大多数的正确关系是**不发生**，而不是"发生后再查出来"。
2. **写时拦截 ≠ 读时检出**：E-B1（脚本违反已登记口径）、E-A2（run 终态未登记）、E-A3（取斑网格口径）、
   E-B2（同名多口径并存）在写入时都可被**义务+机验**直接拦住。
   用"事后检出率"给它们打分，**测到的是设计目标的下界**，不是上界。

**E4a 因此应当被重新定位为"需求排序器"，而不是"否定器"**：它不评价机制该不该建，
它告诉我们**哪些写时义务是承重的**——按事件落档，承重顺序是
**口径/定义登记（T2，4 件）> 前提绑定与参数变更史（T4，3 件）> 受控设计登记（T3，1 件）> run 终态登记（T1，1 件）**。
这个排序对前瞻性 schema 的**字段优先级**是有效输入；对"该不该有五类对象"是**无效证据**。

**仍然成立的三条**（与前瞻/回溯之分无关，不因本修正而失效）：

- **E0 的那一条**：给"双图谱有增益"提供证据的 PoC 语料，7 个缺口全在 T0/T1，且扁平确定性检查 7/7。
  这说明的是**验收体系无法区分"图的价值"与"linter 的价值"**——这是对*实验设计*的批评，不是对*机制*的批评。
- **旗舰能力（关联召回帮评审发现遗漏因素）至今没有正向证据**；本修正把它从"疑似打偏"改回**"未测"**。
- **写时/读时需要拆开验证**：E4a 无法验证前瞻性机制，E4b（新建记录、错误埋在记录之间）才是
  与前瞻性主张同形状的检验；E5 的读数今后一律标注为**"读时检出下界"**。

由此得到一个必须直说的代价：**前瞻性主张原则上无法用任何遗留数据证伪**。若前向验证
（新建工作区跑真实新工作，或 E4b 这类同形状盲测）长期不做，那么该主张的状态只能记为
**「按策略未验证」**，而不能记为「已由纪律保证」。这是本审计的核心结论，与遗留资产无关。
