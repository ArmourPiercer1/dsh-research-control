## 0. 决策摘要：五阶段、两类真实任务接入门槛

**PoC 采用 P0–P4 共五个阶段，按验收 Gate 前进，不以日期或代码量判定完成。**

| 阶段 | 核心目标 | 阶段完成后的新增可试能力 | 真实数据接入级别 |
| --- | --- | --- | --- |
| **P0 — 隔离与样本契约** | 冻结测试范围、隔离工作区、选取最小案例及负例 | 合成数据端到端 fixture | 仅人工筛选样本，不自动接入真实历史 |
| **P1 — PROV/SOSA 来源与事件重放** | `prov:Activity/Entity`、`sosa:Observation/Result`、Run/Artifact 历史映射、确定性重放 | **允许开始真实任务历史轨迹整理（只读、离线）** | **H1：离线历史试接入** |
| **P2 — L0/L1 与历史语义整理** | 结构化 Finding、词汇/Scope/版本、语义确认、引用来源与未知项 | 可形成有来源、带不确定性的真实任务复盘；**允许与正在运行的任务被动并行采集** | **H2 / LIVE_PASSIVE：离线语义整理 + live passive shadow** |
| **P3 — Evidence/Argument 与非单调认识** | 证据关系、论证多路径、攻击/削弱、Assessment/FactStanding、受影响路径 | **允许真实任务旁路生成需人工审阅的论证与风险报告** | **LIVE_REVIEW：live review-only sidecar** |
| **P4 — 双图谱、灵活召回与互操作** | Association/Inference 联合查询、路径来源、JSON-LD 往返、代表性评估 | **允许在明确授权下把建议反馈给真实科研 Agent；完成继续正式开发的 Go/No-Go 评审** | **CONTROLLED_ADVISORY：受控建议（仍不直接写 V1）** |

**针对用户的两个时间点：**
1. **整理既有任务历史轨迹：P1 验收后即可开始**，不需要等待完整 Argument、FactStanding 或双图谱。P1 只承诺来源/事件重建；真正自动做“科研语义复盘”要到 P2。
2. **与真实任务并行：P2 验收后即可做 *被动旁路观察*（live passive shadow）**，不向正在运行的 Agent 提交结果，也不改变任务。P3 验收后可以输出供人审核的科研论证和风险提示；**P4 验收后**才考虑经授权将建议主动送入研究任务上下文。以上三个层次不要混为“接入成功”。

以上 Gate 均以**实际验证完成**为前提。当前只有分支和本计划；**未声称任何 Gate 已通过**。

## 1. PoC 要回答的科学/工程架构问题

1. 使用 W3C 正式名称和语义后，能否准确表示一次科研运行中的活动、观测、结果与数据派生，而不让 `prov:wasDerivedFrom` 冒充科学证明？
2. 能否从零碎任务历史形成 **L0 来源可靠但仍不确定**的结构化研究记录，并经 L1 提供语义稳定的共享结论？
3. EvidenceRelation 和 Argument 的组合能否处理多前提、替代支持、反驳、undercut 及条件性推理？
4. H1 解释错了但独立实验仍支持性能 P 时，能否**只让受影响的支持路径退化**而不删掉独立事实来源？
5. 弱 Association 能否帮助找到潜在遗漏，同时绝不被“洗白”为已验证的因果或 Fact？
6. 离线历史与在线旁路的真实数据是否暴露出当前模型未考虑的失败模式？
7. 从 V1 记录导入/展示、以及 JSON-LD 导出/重放之后，是否仍具有唯一来源、精确版本和可审计的责任边界？

**非目标**：完整 L2–L5 等级、全能 Evidence Adequacy 检查器、通用因果发现、自动真理评分、完整生产数据库迁移、UI 大重构、替换现有 11 个工具、改变 V1 计划/权限、Agent 调度或实验设备控制。Lean 只保留小规模精确命题验证对照，不作为启动前置条件。

## 2. 范围隔离与总体安全约束

### 2.1 仓库及状态隔离

- 本分支**基于 V3 架构 Draft PR #9 当前设计提交**；不得将其误认为已经合并到 `main` 的正式规范。
- PoC 后续代码建议存于 `experiments/v3-semantic-poc/`，测试与 fixtures 随 PoC 单独管理。首批直接调用纯领域逻辑，不接线 `src/host` 正式 Host、DSH adapter、GUI 和冻结 11-tool 面。
- 独立输出位置（示例）：`.poc-data/v3/`，用临时/单独 SQLite 或 JSONL；不写 `.research/**`、V1 的现有 SQLite、Git checkpoint、任务计划或生产 Artifact 注册表。真实运行日志和原始研究文件**不提交到仓库**。
- 所有从 V1 或外部系统读取的数据：只读快照、显式来源 URI/仓库 commit/Run ID、采集时间、内容哈希（若可获得）及导入批次 ID；保留未知/缺失项，禁止捏造事件或补齐缺失科学结论。
- 不把历史 `FACT_RECORDED` 转成新的可信 `FactStanding=ACTIVE`；它只证明 V1 当时登记过一个名为 Fact 的标签。
- **权限**：最小只读凭据、脱敏、路径白名单、不得导出凭据或不应公开的实验数据。允许选择尚不涉密的科学任务历史作为第一批素材。
- **无 Agent 编排**：调度正式研究 Agent、给其投递建议或触发任务由外部系统/用户负责，PoC 服务不得新增隐式唤醒循环。
- **失败隔离**：侧车的错误、超时、LLM 失联和图索引崩溃必须与实际科研任务隔离；不得让 sidecar 变成主任务新的依赖或 Gate。

### 2.2 兼容现有项目

现有 V1 已有 `ResearchHistory` 的 append-only 事件信封、双时序、Run 生命周期（如 `RUN_STARTED / RUN_FINISHED / RUN_FAILED`）、`CLAIM_RECORDED / FACT_RECORDED / ARTIFACT_REGISTERED` 及 Relation 事件；已有 `tests/history-replay`、`tests/semantics` 等回归组，以及 `npm test` / `npm run lint` / `npm run build`。

PoC **首先复用这些历史和测试契约**，但使用非侵入的 adapter 构建新的来源/语义投影。`Run` 是 V1 的执行记录，映射为 `prov:Activity` 时要保留来源和具体活动角色，不假装二者必然一对一等价。

> 当源记录缺少完整 Observation、Artifact 或采样条件时：只能记作 `UNKNOWN / UNRESOLVED`，不能通过语言模型补全为“已发生且可信”的事实。

## 3. 样本与真实任务选择

选取**一个贯通科研案例 + 一个具有不同错误类型的案例 + 一个非科研任务对照**，优先使用可访问、经授权、能定位原始文件的历史，不假定以下项目的日志现在已可读取。

| 候选 | 关注语义 | 作为何种样本 |
| --- | --- | --- |
| **numerical-streak-camera**（条纹相机数值仿真） | 场模型/数据版本修订、数值诊断、轨迹、后处理结果、异常校准/收敛判断 | 首选**科研历史回放**；有新计算任务时也可 live passive |
| **UED-Diffraction-Sim**（衍射仿真） | 不同算法与输入、独立核验、GPU 输出、理论/计算适用 Scope | 第二类**科研历史/在线观测** |
| **dsh-agent-team 工具接线/测试任务** | Run、错误日志、修复、验证与实际科研 Assertion 的区别 | **负向对照**：工程完成不自动产生科学 Fact |
| **Rhodotron 微束团理论或数值研究** | 理论推导、理想化预测、真实物理/工程迁移与未闭合条件 | 后续的**跨 World 压力测试** |

样本最少包括：一次有成功输出的 Run；一次失败、中止或没有有效科研结果的 Run；同一数据经两次 Analysis 产生不同结果的过程；一条后来受到质疑的推理；至少一个真实未知项。如果这些材料实际没有源记录，应明确标为缺失或使用合成 fixture；**不得声称真实源已齐全**。

真实在线任务优先选择低风险仿真/数据分析，而不是实际设备操作；即使任务包含实验控制，PoC 也只能做数据观察侧车。

## 4. 五阶段详细实施

### P0 — 隔离运行、样本与验证合同

**目标**：获得可重复、可失败的最小实验环境；不实现完整产品接口。

**工作**：
- 记录 branch base commit、Node/package scripts 和已有 `HistoryEvent` 契约；准备独立测试目录和 `poc-run` 入口（名称建议，未冻结）。
- 建立最小合成 fixture：成功实验、失败采集、同源不同分析、独立支持路径+错误机制、弱关联不能推理。
- 定义导入记录的最小来源 envelope：来源项目/Workstream、Run/事件 ID、事件序号、原始发生与登记时间、快照/commit、原始内容引用或哈希、导入时间、访问边界。
- 建立测试所需的最小 golden annotation：哪句文本**真的**包含哪个实验结果/断言/错误；哪些信息未记录。标注者、依据和分歧需留档。
- 建立只读/拒绝写入机制及日志脱敏约束；测试源路径不在隔离边界内时必须拒绝。

**Gate P0（全部满足）**：
- 无修改 V1 `.research/**`、生产 DB、现有工具与主任务的代码路径。
- 合成 fixture 覆盖成功、失败、多分析版本、论证路径争议与未知条件。
- 明确“来源记录”“研究者推测”“LLM 补充建议”之间的标记，不允许混存。

**对真实任务的权限**：仅允许人工选样本和准备脱敏快照；不启用自动历史导入。

### P1 — W3C 来源/观测基础与事件重放

**目标**：能无损、可回放地整理一次真实任务的事件和数据产生过程。

**工作**：
- 最小 `prov:Activity/Entity/Agent`、`prov:used/wasGeneratedBy/wasDerivedFrom` 投影及相应 `sosa:Observation/Result` 映射；保留 W3C 对齐例外，不强行把纯软件或理论输出变成 SOSA 测量。
- 只读解析 V1 `ResearchHistory` 和原有 `Run/Artifact/Relation`，用版本化 Crosswalk 映射来源链；分开数据派生与逻辑推理。
- 在隔离本地存储中形成可以重复构建的轨迹视图（Run 时间线、输入产物、执行状态、未知项、源事件定位）。
- 接入 synthetic 的失败实验及真实来源反例；未知传感器、设备或分析程序只做“来源未知”，不能强制建立伪 `sosa:Result`。
- 可以尝试轻量 JSON-LD/PROV 输出；完整双向语义交换留到 P4。

**Gate P1（打开真实历史试接入）**：
- 由相同历史快照重新导入，两次的**稳定身份、有效事件顺序、可恢复来源引用和轨迹结构一致**；重复导入幂等。
- 100% 导入对象具有可追踪源定位**或明确的缺失来源标记**，不允许出现伪造的源 Run/Artifact；已知实际 V1 记录不得静默丢失。
- 正确区分实际发生的运行、计划 Task、原始数据和加工结果；失败 Run 可保留而无需伪造正常结果。
- **零向 V1 生产端回写**，零把 `FACT_RECORDED` 自动升级为科学确认 Fact。

**解锁：H1 — 可开始真实历史任务轨迹整理**。优先挑选一个成功和一个失败/中止的真实 Run，导出只读轨迹报告，定位来源缺口；此时**不承诺已解析其科学主张**。

### P2 — L0/L1 语义规范化与历史科研复盘

**目标**：从历史或新出现的自然语言任务记录中，形成**可追溯的候选科研陈述**及规范术语版本。

**工作**：
- L0：结构化自然语言 `ResearchFinding`，显式对象、活动/结果、推理方式（若存在）、原文片段、来源位置和不确定项；不凭 LLM 自述确立证据有效性。
- L1：结合 `skos:Concept`、WorldContext、ResearchScope 和人工/受授权语义确认，明确术语与适用边界。允许 `NEEDS_CLARIFICATION`，不要为了提高完成率猜出原作者意图。
- 对历史轨迹生成受来源约束的复盘视图：已实际产出的结果、拟议科研解释、与原始日志的差异、模型自动提出的澄清问题；不自动 Fact 化。
- 处理语义版本变化及源证据删除/丢失提示。通过结构化事件保持 L0 原稿与 L1 候选互不覆盖。
- 开发仅输出侧车自身数据的 live passive ingestion：外部任务系统把**镜像事件/只读快照**提供给 PoC；若获取方式需要轮询或触发，由外部执行系统负责。

**Gate P2（打开 live passive）**：
- 已从至少两个不同性质的真实轨迹片段生成科研复盘，并进行逐条人工对照；报告里所有被认定的“原始事实”均能定位源内容，任何推断/猜测单独标记。
- L0 可以保留暂不确定的论点、L1 只有在语义确认完成时才标为稳定；开放歧义可持续存在。
- 被动侧车中断、输入重复、顺序乱序、主任务异常终止时不影响主任务，也不更新 V1。
- 观察服务不向研究 Agent、Task、Gate 或 canonical Plan 回填任何结果。

**解锁：LIVE_PASSIVE — 可以和真实任务**并行运行只读旁路观察**。它能持续整理科研轨迹，但主 Agent 默认完全不受影响；不声称能当场诊断科学错误。

### P3 — EvidenceRelation、Argument 与非单调科研评价

**目标**：论证体系能正确表达新证据、被质疑的解释、多个支持路径和修订影响。

**工作**：
- `EvidenceRelation` 表达单项结果对具体 AssertionRevision 的证据倾向和条件；没有完整统计模型时不臆造 `P(H|O)`。
- `ArgumentRevision` 表达前提 AND / 多条替代支持 OR，推理方法（演绎、归纳、统计、溯因、类比、因果等）、Scope 和开放义务；允许联合 Observation/结果而不必先把各单项评分求和。
- 实现本地、无生产影响的 Assessment 和 `FactStanding` 状态历史；受攻击的是哪个论证/前提/适用性须能追踪。
- 针对 H1 错误但独立实验证据仍支持 P 的案例，验证 selective impact；区分 Rebuts（攻击结论）和 Undercuts（攻击推理适用性）。
- 对历史和 live passive 来源**生成候选**证据/推理报告，并给出源文锚点和“缺失重要输入”的提示；未经审查不可转成正式 Fact/Task/Obligation。
- 必要时添加最小 Theory 严格对照：一条精确形式命题的可信验证回执，明确其数学可信基和物理适用范围是分开的。

**Gate P3（打开真实任务评审侧车）**：
- “独立支持路径保留”“旧解释失效但结果可能仍成立”“形式推理有效而工程适用性失败”三个反例均通过。
- Argument 与 Assessment 事件可重放；已有判断不能无声覆盖；错误来源可定向定位受影响节点。
- 自动生成报告经人工核对不出现**把相关性说成因果、把 Run 测试通过说成科研证明、把 LLM 置信分说成 FactStanding**的高风险误报。
- 与真实任务并行时报告发布在隔离审查渠道或独立文件，默认**仅供人阅览**，不得自动注入主 Agent 指令。

**解锁：LIVE_REVIEW — 可以对真实任务旁路提供“候选论证、依赖缺口、异常及风险”人工复审报告**；依然只读，绝不自动干预科研执行。

### P4 — 双图谱、联合召回、互操作与真实任务 A/B

**目标**：验证我们最核心的新能力是否有增益：在不制造虚假科学推理的前提下，用关联图谱帮助科研评审发现可能遗漏的因素。

**工作**：
- 从同一来源事件和科研知识产生 Inference Graph / Research Association Graph 两个**可重建的视图**。弱关联可来自设备拓扑、程序数据来源、已登记统计发现或有来源的经验联想。
- 提供**自由可组合的读操作**：调用方 LLM 自选图、起点、方向、关系过滤、hop、剪枝及迭代；不预制“固定三跳必须查完”的隐藏工作流。
- 每次返回被召回对象、逐边类型、完整路径、Provenance、Scope/时间/版本、过滤与截断信息；结果注明“相关不等于因果/已支持”。
- 按 [W3C Alignment](../architecture/W3C_ALIGNMENT.md) 检查 JSON-LD/RDF 导出、再导入后的精确身份与含义（特别是从未确认的 Assertion 不得转为公共事实 triple）；使用 SHACL 仅验证其定义的形状。
- 对同一批脱敏科研任务进行四组离线 A/B 比较：**原始文本、仅 Inference Graph、仅 Association Graph、交替双图谱**。LLM 模型和可见原始证据尽量控制一致，由人工标注者核查问题召回质量。
- 以极小的真实并行科研任务试运行“可控建议”通路。**必须由用户或外部 Agent/权限治理系统明确授权**；建议仅为可审阅材料，不自动修改科研 FactStanding、Task、实验配置或设备命令。

**Gate P4（PoC 完成评审）**：
- 引用和图路径可重放；无“相关性→因果/义务/科学事实”自动提升。
- W3C 交换保留对象 ID、Revision、关系语义、来源、未知项、正式与非正式的接纳状态；任何不支持的字段有显式 loss report。
- 对照实验提交问题发现率、无根据质疑率、路径可溯源比例、检索成本和错判案例；**不要求预先断言双图一定优于其他组**。若代价高或误报过多，PoC 应保留负结论。
- 对至少一个 live task 验证“建议由外部系统按授权交付、PoC 出错不影响主任务、用户可立即停止侧车”；仍然**不写入 V1 生产科研状态**。

**解锁：CONTROLLED_ADVISORY — 可讨论控制范围内对真实科研任务反馈检索和审查建议**；Go/Iterate/Stop 的结果决定是否进入后续正式开发 PR。

## 5. 真实数据接入级别与强制边界

| Level | 最早阶段 | 允许读取 | 允许输出 | 不允许 |
| --- | --- | --- | --- | --- |
| **H0 合成** | P0 | synthetic fixtures | 离线测试/模型输出 | 访问未经授权的真实轨迹 |
| **H1 离线真实历史** | P1 Gate 通过 | 完整性可验证的归档 Run、ResearchHistory、Artifact 只读副本 | 隔离重建、来源差异、未知报告 | 写回旧历史、推断缺失科研事实 |
| **H2 历史科研整理** | P2 Gate 通过 | H1 + 任务文字、程序/文档只读样本 | L0/L1 候选、人工可审复盘 | 未确认 L1 直接进入全局 Fact |
| **LIVE_PASSIVE 在线被动** | P2 Gate 通过 | 当前科研任务**只读镜像** | PoC 自有状态/日志 | 干预科研 Agent、改变任务/计划/权限 |
| **LIVE_REVIEW 在线审查** | P3 Gate 通过 | LIVE_PASSIVE + 论证输入 | 单独的人类审查报告 | 自动把报告发为 Agent 指令或 Gate |
| **CONTROLLED_ADVISORY 受控建议** | P4 Gate 通过 | LIVE_REVIEW + 双图路径 | 用户/外部调度明确批准的候选建议 | 直接修改主任务科研状态、执行实验、自动批准 Fact |

本文旁路接入级别一律用 `LIVE_PASSIVE / LIVE_REVIEW / CONTROLLED_ADVISORY` 标识（原 `L1/L2/L3` 简写自 EB3 入库复核 M2 起弃用）；`L0/L1` 与 `L2–L5` 恒指科研形式化等级（[架构基线](../architecture/ARCHITECTURE_BASELINE.md) §4），不再与接入级别共用字母。

## 6. 质量指标与停止条件

每个 Gate 的回归报告至少包含：输入快照与哈希、可复现运行指令、通过的正例与负例、失败/未知项、数据来源和权限范围、差异报告、受影响的 V1 记录（必须为空）、审查者意见。

关键零容忍项目：
- 任何对 V1 生产研究 DB、`.research/**`、canonical Plan、Gate 和 Agent 权限的非授权写入；
- 将 `FACT_RECORDED`、LLM 评价、检索相似、联合关联边或 SHACL 通过误写成“科学事实已证明”；
- 丢失原始事件来源/旧修订，或者为了让验证通过凭空制造 `sosa:Observation` / `sosa:Result`；
- PoC 故障阻塞、终止或更改真实科研任务。

科研质量指标不采用一个虚构的“科学正确率”：分别报告 ①源记录可追踪和未解析覆盖率；② L0/L1 语义错误与未知项；③ 已知前提缺口的检出率；④ 不适用的反驳/因果推理误报；⑤ 召回噪声、人工负担和资源成本。每个指标附样本量与具体案例，避免小样本的过度概括。

在出现违反语义不变量、迁移存在不可追踪有损、重复伪造强论证，或者性能/负载影响真实任务时：**立即停止提升接入级别**，保留可复现失败记录、回到最小抽象审查，不通过添加隐式例外来掩盖问题。

## 7. 工作模式与阶段产物

### 工作与权限分工

- **PoC 域开发者**：独立测试、适配、语义域模块；无正式 Host/生产写权限。
- **科学案例审查者**：提供经授权来源、人工标注具体科学含义和误报；不将随意模型评分视为科学真理。
- **W3C/论证审查者**：核对标准精确映射，拒绝强行等价或弱关联自动闭包。
- **外部 Agent 执行系统**：管理正式科研任务及 sidecar 的生命周期、授权、日志镜像和必要反馈。
- **基础设施服务**：仅实现状态、约束、来源、查询与审计；**不自行启动/调度 Agent**。

### 建议目录（尚未创建，非硬性开发契约）

```text

  V3_POC_EXECUTION_PLAN.md      # 本文件
experiments/v3-semantic-poc/    # 待 P0 正式开始时再建

  reports/                       # 不含未授权真实样本
```

每阶段结束交付 **Gate Report**（输入、输出、证据、负例、风险和下一 Gate 判定）；PoC 输出不写回 `docs/architecture` 的已同意原则，若发现架构缺陷，单独提议 ADR 修订。

## 8. PoC 的最终决策

| 结论 | 条件 | 后续 |
| --- | --- | --- |
| **GO** | P0–P4 核心语义和负例通过；W3C 往返无错误增强；真实任务观察无副作用；科学审查有明确可追溯的增益或可接受成本 | 另立正式 V3 实施契约，分模块推进，另开实施 PR |
| **ITERATE** | 基础模型正确，但 EvidenceRelation/Argument、数据类型映射或召回策略出现可定位的问题 | 针对失败抽象修订并重测，不全面扩展功能 |
| **STOP** | PoC 持续误将弱关联当科学证明、无法稳定保留来源或影响真实任务，或被迫引入大量隐式例外 | 暂停产品化，保留失败经验并重新审查语义 |

**本文件本身不意味着 P0 已开始、任何历史数据已读取、任何真实任务已接入，更不意味着正式 V3 开发已获批准。**
