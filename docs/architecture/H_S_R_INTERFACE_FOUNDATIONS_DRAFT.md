# 上层领域接口基座：调用包络、呈现边界与兼容纪律

> **PR #47 · DRAFT-PROPOSAL · 2026-10-29。** 把[领域交互契约](H_S_R_INTERACTION_CONTRACT_DRAFT.md)（PR #42，未合并）的 IC-\* 操作语义落到**对外接口形态**：调用包络、错误与授权呈现、两视图脱敏、幂等、分页、双时相参数、异步检查、兼容纪律。编码基线见[Schema 基座](H_S_R_SCHEMA_FOUNDATIONS_DRAFT.md)；逐操作形态见[接口目录](H_S_R_INTERFACE_CATALOG_DRAFT.md)。
>
> **本文件不是服务设计**：不规定 HTTP/MCP 路由、函数签名、进程边界、事务隔离、调用顺序或部署拓扑。H/S/R 是**职责正交**，不要求三个服务（IC 头部原文）。本文只裁决"一次调用怎样被写成请求与响应，才能不违反领域不变量"。**Proposed，不表示已实施。**

## 1. 与既有工具面的关系（先划边界）

| 编号 | 规则 |
| --- | --- |
| SI-01 | 既有 11 个 `research_*` Agent 工具（ARCHITECTURE §7.2，属**冻结根文档**）的名称、参数、结果与错误语义**全部保持不变**。HSR 接口是**新增命名空间**（建议前缀 `hsr_`），不与既有工具共用名字，也不改变既有工具的行为。 |
| SI-02 | **新增任何工具名都是冻结面变更**：§7.2 清单与权限矩阵在 `ARCHITECTURE.md` 内，落地需走冻结变更流程 + `Frozen-Face-Review:` 人工标记 + `tests/tools/permissions.test.ts` 的禁止操作清单同步。本轮只出设计，不改文档、不改代码。 |
| SI-03 | HSR 对象与 V1 记录（Fact/Claim/Artifact/Relation/Run/PlanFork…）是**两套身份**，不存在自动同步、自动镜像或共享 ID。跨层联系必须是**显式登记**：HSR 侧登记 Association/来源引用，V1 侧沿用其既有来源记录；两边都不因对方存在而自动获得任何语义（DF-04、ID-07）。 |
| SI-04 | 分层沿用既有约束：工具（顶层）→ 服务 → 领域，工具不得直连领域；插件不得 import 宿主内部包（INV-PERM-5（`ARCHITECTURE.md` §2.2 依赖方向规则））。HSR 接口只是多出一组工具入口，不新增旁路。 |

## 2. 调用包络

### 2.1 请求侧

| 要素 | 形态 | 规则 |
| --- | --- | --- |
| `contract_version` | 可选整数 | 缺省 = 服务端当前版本；**检查类与写入类响应必须回显实际生效版本**（SF-63） |
| `space_id` | 必填（除注册表读） | 每次调用只针对一个空间；不存在跨空间调用（ID-02、SP-04） |
| 主体上下文 | **调用方不得自报身份** | 主体、`run_id` 由宿主执行上下文注入并冻结（沿用既有 `allowedActorKinds` 与 `requiresRun` 机制；既有组装期自检要求 `requiresRun ≡ (access === 'write')`，故 HSR 只读工具**不得**要求 run、写工具**必须**要求 run，该既有约束原样继承）；请求里出现的 `actor` 字段只作**声明性主体**（"某人声称…"），绝不作为授权依据（IC-02、A6/A7 的主体区分） |
| `client_request_id` | 写操作必填 | 幂等键，见 §5 |
| 时间条件 | `recorded_as_of` / `described_at` / `described_during` | 查询类可用；缺省必须回显（T-05） |
| `version_selection` | 枚举 | 唯一允许表达"跟随当前"的位置；正式声明槽位永远精确（SF-23、ID-05） |

| 编号 | 规则 |
| --- | --- |
| SI-10 | 请求里**禁止**出现：`latest` 引用、跨空间目标引用、被屏蔽目标的任何标识、调用方自报的 `recorded_at`（登记时间由系统产生）、任何用于跳过检查的标志位。修订类请求（追加新修订）另禁止提交 `object_kind` 与 `space_id`：二者在 `r1` 固定，提交即 `TOOL_INPUT` 拒绝且不产生记录（ID-01、ID-02、SS-10）。 |
| SI-11 | 稀疏提交合法（只提交想声明的槽位）；服务端展开时未提交的可空槽位一律 `ABSENT`，**永不**填默认值（SF-04、UN-02）。 |
| SI-12 | 请求体非法（语法、未知键、类型、缺 `kind`）→ 工具层 `TOOL_INPUT`，业务层不落任何记录；`F-SCHEMA-INVALID`（可解析为记录但非正式对象）→ **落 H 原始记录**而不是拒收（IC-H3、`SL0-COM-01`）。 |

### 2.2 响应侧

```
{ status, echo{space_id, contract_version, recorded_as_of, described_*, version_selection},
  data | failure{domain_code, ...}, boundary{coverage, truncated, limit_applied},
  report_refs[] }
```

| 编号 | 规则 |
| --- | --- |
| SI-13 | `echo` 是**必填**：任何查询结果必须回显实际生效的两个时间、视角、版本选择、契约版本与所采用的投影（T-01、T-05、IC-H6）。缺回显视为实现缺陷，不是可选元数据。 |
| SI-14 | `boundary` 只在结果可能不完整时出现，且遵循 SP-03 的**按权限量粒度**：对被屏蔽范围无可见权时，一律 `NOT_DISCLOSED`（既不说是也不说否），永不给计数、标识、时间分布或可反推存在性的派生量。 |
| SI-15 | 空结果必须携带 `boundary`，使"没查到"不被读成"不存在"（C12、CS-24）。 |


### 2.3 `space_id` 的宿主映射（未裁决，登记为实现前置）

| 编号 | 规则 |
| --- | --- |
| SI-16 | `space_id` 是每次调用的必填槽位并在 `r1` 固定（ID-02），但**它与宿主既有概念的映射尚未裁决**：候选是「一 Project 一空间」「一 Workstream 一空间」或独立于二者的新维度；V1 侧没有 space 概念（`schema/common.schema.json` 无 space，V1 对照表亦记「不同维度，不互相推导」）。裁决前不得由实现自行选择——空间粒度一旦定错，隔离边界与可见性判定（SP-03）会整体错位且无法事后重划。 |
| SI-17 | 裁决前允许的实现形态：单一默认空间（全部记录同空间），使接口与形态可以先被测试；该默认必须在配置中显式命名，不得隐含在代码里（避免"默认空间"变成事实上的全局空间而无法拆分） |
## 3. 错误模型（不改既有工具错误词表）

既有工具层错误码 `TOOL_ACTOR_FORBIDDEN / TOOL_RUN_REQUIRED / TOOL_INPUT / TOOL_ABORTED / TOOL_NOT_IMPLEMENTED / TOOL_SERVICE` 是宿主映射面，**保持不变**。领域失败码通过结构化 `detail` 承载，`ToolError.detail` 在宿主侧是开放 `Record`，但既有实现只用到 `serviceCode`/`step`/`path`/`tool`/`plannedService` 五个键；本层**沿用这五个键**，并只额外登记一组前置专用键 `{serviceCode:"PRECONDITION_FAILED", step:"expected_head_revision", expected_head_revision, actual_head_revision}`（见 SI-24）。除此之外的新键即新造平行字段，须先登记：

```
ToolError{ code: 'TOOL_SERVICE', detail: { serviceCode: 'F-WITHHELD', tool: 'hsr_object_get', step: 'resolve_reference', path: '/fields/world_membership' } }
```

| 编号 | 规则 |
| --- | --- |
| SI-20 | 领域失败码集合**只引用**交互契约 §1.1 的 `F-*`，本层不新增、不改写其语义。若需要新码（见 SI-24），那是**对 PR #42 的修订请求**，登记在[Schema 决策与遗留](H_S_R_SCHEMA_DECISIONS_DRAFT.md)，不在本层私自扩表。 |
| SI-21 | 写操作的"保存成功但结构不完整"是**成功响应 + `failure` 附注**：对象已保存（DF-07、IC-01），响应 `status = ACCEPTED_WITH_FINDINGS` 并携带新 `report_refs[]`；**不得**返回工具失败，否则实现者会被迫拒绝保存（违反 DF-07）。 |
| SI-22 | 授权类失败严格按 SP-09 分道：无写权限 → `F-DENIED-WRITE`（目标空间不产生任何记录、不返回内容）；有写权限但缺业务授权 → `F-DENIED-AUTH`（登记为未生效声明 `AUTHORITY_UNVERIFIED`，响应成功但 `status = ACCEPTED_UNVERIFIED`，不进任何投影）。 |
| SI-23 | 检查器/资源不可用 → `F-CHECK-UNAVAILABLE`：这是**响应成功**且报告记 `INDETERMINATE(CHECKER_UNAVAILABLE)`，绝不折叠成"检查未通过＝结论为假"（IC §1.1、NEV-05）。 |
| SI-24 | **待回写契约层的新码（修订请求，非本层裁决）**：修订类写入的乐观前置（`expected_head_revision` 不匹配）在既有 `F-*` 中无对应码；`F-CONFLICT` 是**语义**上的"可能同一事项不相容主张"，不得挪用为并发前置失败。建议新增 `F-PRECONDITION-REVISION`（拒绝写入、不产生记录、可重试）。在契约层采纳前，实现只能返回 `TOOL_INPUT` 级拒绝并在 `detail.precondition` 说明——该退化必须在测试中钉住。 |
| SI-25 | 错误响应同样受 §4 的脱敏约束：错误消息、`detail` 字段、日志行都不得泄漏被屏蔽目标的标识、计数或存在性（SP-07、RPT-09）。 |

## 4. 两视图与存在性侧信道防护（接口层强制点）

| 编号 | 规则 |
| --- | --- |
| SI-30 | 审计视图对**同时对目标空间与被屏蔽范围有可见权**的调用者开放；其余调用者一律得到 `sanitize()` 后的呈现视图（RPT-09、SP-10）。视图选择是**服务端授权判定**，不接受调用方参数请求审计视图。 |
| SI-31 | 脱敏是纯函数：`presented = sanitize(canonical_record, authority_class)`。同一记录 + 同一授权类必须得到**逐字节相同**的响应形态（SF-50 规范字节形态；XC-25）。禁止把随机化、时间戳、内部计数混入被脱敏的字段。 |
| SI-32 | 脱敏后必须把 `FAIL(REF_UNRESOLVED)` 与 `INDETERMINATE(WITHHELD_REFERENCE)` 折叠为同一个对外码 `UNVERIFIABLE_REFERENCE`，`coverage → NOT_DISCLOSED`，层级 `verdict → UNVERIFIABLE_TO_YOU`（RPT-09、RPT-10）。 |
| SI-33 | **形态与量级恒定**：同一操作在"目标存在但无权"与"目标不存在"两种世界下的响应**形状、字段集合与量级**必须一致——含被截断字符串的占位长度、数组用固定空集合、错误层级用同一码；因此实现不得对"找不到"做提前短路（早退是最主要的时延侧信道，SP-07）。 |
| SI-34 | 缓存/CDN/日志必须按授权类分键；禁止把审计视图写入可被无权方读到的缓存、错误上报或 Agent 上下文包（SP-07、IC-P2）。 |
| SI-35 | 核验权 ≠ 写权限：能写入某空间不使其能核验跨空间依赖，响应仍是 `UNVERIFIABLE_TO_YOU`；系统不得提示"先取得可见权以提高层级"（RPT-11）。 |

## 5. 写语义：追加、幂等与前置

| 编号 | 规则 |
| --- | --- |
| SI-40 | 写操作只有**追加**效果（新对象/新修订/新记录/新报告），没有就地改写（IC-01）。接口不得提供 PATCH 语义；"修改"= 提交新修订。 |
| SI-41 | 幂等：同一 `(actor, client_request_id)` 的重复请求必须返回**首次结果**且**不产生第二条记录/第二个修订**（网络重试是常态；重试造成双修订是缺陷）。幂等键的主体粒度固定为**宿主注入的主体标识本身**：USER 取 `actor.user_id`，AGENT 取 `actor.run_id`；缺该字段即不参与去重，每次都产生新记录——宁可重复，不可吞掉一次真实登记。去重窗口时长属实现参数，必须登记为配置并写测试：窗口内重试返回首次结果，窗口外重试按新请求处理并可能得到 `F-PRECONDITION-REVISION`（SI-24），且两条记录都必须完整可审计（禁止窗口外静默合并）。 |
| SI-42 | 修订类写入必须携带 `expected_head_revision`；不匹配 → 拒绝写入，不产生记录（乐观前置，避免 last-write-wins 覆盖历史）。 |
| SI-43 | 批量接口只做**同质追加**（一批彼此独立的新对象/新修订），不得表达跨记录事务、不得"原子地"更新轴状态或跨对象改写（IC-04：跨轴效果必须由另一个显式操作产生）。部分成功逐条报告，禁止静默丢弃。 |
| SI-44 | 任何接口都不得提供"设当前版本""标记已验证""同步为现状""一键对齐"之类的原语——它们把派生投影写回真源（AX-03、DF-03、IC §7）。 |

## 6. 读语义：分页、双时相与投影

| 编号 | 规则 |
| --- | --- |
| SI-50 | 分页沿用既有**约定**而非既有游标：游标制、默认页大小、超上限**拒绝而非钳制**（现状默认 100 / 上限 1000，越界 `TOOL_INPUT`）、每页回显 `limit`/`next_cursor`/`exhausted`。**HSR 使用自己的不透明游标，不封装既有的 `after_seq`/`before_seq`/`next_after_seq` 整数 seq 协议**——那套 seq 是 per-workstream 的 V1 事件日志序号，而 HSR 记录是否进入该日志正是未裁决项（SD-07）；把它当作 HSR 的排序轴等于偷偷预设裁决。游标可排序轴本身依赖 SD-07，本层只规定游标必须自包含（SI-51）且不暴露底层 seq。 |
| SI-51 | 游标必须**自包含知识截点**（编码 `recorded_as_of` 与查询指纹）：晚到登记不得使同一游标翻页时重复或漏项；游标跨越截点 → 拒绝并要求新查询（否则"历史重建"结果不可复现，T-02）。 |
| SI-52 | 排序不得引入语义优先：不得以"更可信/更可能正确"排序；允许的排序键是时间类、标识、显式程度值（且须带尺度引用，`RL1-08`）。 |
| SI-52a | **默认全序必须唯一确定**：缺省按 `(recorded_at, record_id)` 升序，二者都相同时按 `record_id` 字典序打破平手，使游标分页不重不漏。排序键与方向必须编码进游标；换排序键即作废旧游标并要求新查询（否则同一游标在不同键下指向不同位置，翻页会静默漏项）。返回顺序不得被解释为语义权重（SI-52）。 |
| SI-53 | 双时相读：`recorded_as_of` 与 `described_*` 可任意组合；实现顺序固定为**先**按知识截点过滤可见记录，**再**按对象时间过滤（IC-H6 不变量），两步不得交换或合并。 |
| SI-54 | 上下文编译（给 Agent 的上下文包）预算不足时返回**缺口清单**或拒发，绝不编造完备上下文；必需前提、量词范围、World 标识、版本引用不得静默截断；条件性内容必须带 `OPEN` 义务与继承路径（IC-P2）。 |
| SI-55 | 投影（状态视图、摘要、看板、导出）不得生成新状态、新程度值或通过率；省略某轴必须显式标注"本视图未包含 X"（AX-02、IC-P1、IC-P4）。导出必须逐条 `lossReport`（IC-P3）。 |

## 7. 异步检查与报告生命周期

| 编号 | 规则 |
| --- | --- |
| SI-60 | 检查是**独立操作**，不隐含在写操作中改变对象（IC-03）；写响应可携带首轮 `report_refs[]`，但报告与对象是两条不可改记录。 |
| SI-61 | 每次检查产生**新** `report_id`；同一目标 + 同一契约/检查器版本重复检查产生内容相同但标识不同的新报告，绝不覆盖旧报告（RPT-01、IC §1.1 `F-RETRYABLE`）。 |
| SI-62 | 长检查返回 `report_id` + 轮询/等待参数；超时不是失败也不是通过：报告 `INDETERMINATE(CHECKER_UNAVAILABLE)`，可重试（SI-23）。 |
| SI-63 | 报告读取受 §4 视图规则约束；有权主体事后复核仍能看到完整审计视图（SP-10）。 |

## 8. 兼容与能力发现

| 编号 | 规则 |
| --- | --- |
| SI-70 | 服务端提供能力声明：当前 `contract_version`、`schema_version` 集合、规则集版本、已注册词表及其版本、支持的时间视角与投影类型。检查与写入响应必须能被追溯到这些版本（SF-63）。 |
| SI-71 | 兼容纪律 = SF-61/SF-62 的接口侧：新增可选参数/可选响应字段/新枚举值 = 兼容；删除字段、改含义、把可选变必填 = 破坏，需新版本并显式分界；已发布参数**永不复用名字表达新含义**。 |
| SI-72 | 弃用是**登记**：接口项标记 `DEPRECATED(introduced_in, note)` 并保留行为，使历史请求可重放；禁止让旧请求静默改语义（SF-64）。 |
| SI-73 | 只读回放要求：给定一份历史请求包络与截点，重放必须得到与当时一致的呈现视图（同一脱敏函数与同一版本），否则审计无法复现（RPT-01、SF-63）。 |

## 9. 负面清单（接口层永不提供）

不提供：就地修改/删除已登记记录的原语；跨空间读取或"临时穿透授权"（SP-04）；`latest` 引用参数进入正式声明位置；任何自动合并、自动重定向引用、自动把机器提示升格为主体主张（ID-07、AS-CF-3）；任何自动补全（默认值、模板、相似度）；任何把检查 PASS 折算为接纳、把 `UNDERCUT`/`REBUT` 折算为"已反驳"、把权限过滤折算为否定的隐式转换（DF-01、DF-05、CN-04、RPT-05）；任何"因为如实声明 `UNKNOWN` 而降级"的路径（UN-06）；任何自动唤醒/分派科研 Agent 的接口（运行编排在系统之外）。

## 10. 落地的最小验证预期（供后续测试设计，非已运行）

1. **侧信道**：SI-33 的形态/量级恒定用例 + 时延早退检查（"不存在"路径与"无权"路径执行同一工作量）+ 缓存分键检查。
2. **幂等**：同一 `client_request_id` 重放 3 次仅 1 个修订；超窗后按新请求且前置失败路径被钉住。
3. **保存不被阻断**：必填缺失（`F-INCOMPLETE`）必须是成功响应 + findings；`F-SCHEMA-INVALID` 必须落 H 原始记录。
4. **授权分道**：`F-DENIED-WRITE` 不产生任何目标空间记录（含"未生效声明"）；`F-DENIED-AUTH` 产生但不进投影。
5. **回显完备**：所有查询响应缺 `echo` 即测试红。
6. **游标稳定**：翻页过程中插入晚到登记，既有游标序列不重复不漏项。
7. **报告不可覆盖**：重检后旧 `report_id` 内容逐字节不变。
8. **回放**：历史请求包络 + 截点重放得到同形呈现视图（SI-73）。
