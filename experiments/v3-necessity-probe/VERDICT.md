# 方向性判据：这套前瞻性设计大概率对 / 跑偏 / 错？

## 判据一句话

**形状大致对，正当性讲错了，验收体系用错了尺子。**
「写时登记」这套动作**大概率对**，但它成立的理由是**可审计**，不是**帮人发现错误**；
而当前整个门禁体系是拿"能不能发现错误"给它打分——**这就是跑偏的地方**，且已经跑偏了一整轮（P4 绿灯）。

## 分层判据


### ① 跑偏（证据较强，已证实）：用"检测率"给本体价值打分

- **已证实**：给"双图谱有增益"提供全部证据的 PoC 语料，7 个植入缺口**全是完整性缺口**，
  一个约 60 行、单趟、零图、零 LLM 的扁平一致性检查器 **7/7**（`e0/decontaminated.mts`，本机复跑）。
  脱敏语料（剥掉写在正文里的答案标签）后四臂读数**一字不变** → 语料自身泄漏答案，任何在它上面做人/LLM 评分的 A/B 无效。
- **已证实**：**P4 的验收体系对此完全无感**——四臂 + 查询/笔记成本 + 「无断言状态 ≠ 未考虑」的语义约束，
  任何一条都区分不了"图的作用"与"一组谓词的作用"。
- **合理推断**：所以"双图谱被证明有增益"这一步**从未成立**；门禁全绿只说明"实现符合验收条款"。
- **推翻它的最小实验**：在同一语料上加一臂"扁平谓词集"，若它 <7/7，我的复现就有问题。（我已复现，等别人再复现。）

### ② 大致对（证据中等）：写时登记的**形状**

按真实修正事件（E4a，9 件 / 3 个真实项目，经独立复核重判）排出的**承重登记动作**：

| 排序 | 登记动作 | 真实事件数 | 需要什么 | 需要图吗 | 需要五类对象吗 |
|---|---|---|---|---|---|
| 1 | **口径/定义登记**（这个量怎么算出来的 + 换过时留痕） | 4（44%） | 一条记录绑定量与定义式 + 脚本版本 | **否** | 否（Concept 一个就够） |
| 2 | **声明↔工件完整性对账** | 2（22%） | 确定性谓词（清单覆盖、担保是否存在、路径是否悬空） | **否** | 否 |
| 3 | **前提 + 参数变更史** | 1（11%） | 结论→前提→工件指纹；参数变更留痕 | 半个（一跳） | 否 |
| 4 | **受控设计登记**（什么被控住/什么共变） | 1（11%） | 设计记录 | 否 | 否 |
| 5 | **run 终态登记** | 1（11%） | run 有终态字段 | 否 | 否 |

- **合理推断**：五项里**没有一项需要图遍历或多跳召回**，也没有一项需要五种对象同时存在。
  承重的是**"把声明登记下来 + 和工件对账 + 换过时留痕"**这三件事，字段维度远小于当前 G1 契约的重心。
- **注意分寸**：这仍是**遗留材料**上的排序（用户已裁定遗留材料不能否定前瞻性设计）。
  它的正确用法是**给前瞻性 schema 排字段优先级**，不是判定"该不该建"。

### ③ 讲错了的正当性（证据中等）："帮人发现隐蔽错误"

- **已证实（本轮 E4b′，n=4×2，同模型 flash-next）**：T2/T3/T4 各造一案 + 范例，
  **A 臂（只有扁平 JSONL + 三通道，零登记义务）4/4 全部抓到隐藏错误**，并且主动算出我埋在库里的定量杠杆
  （5.99 = 二维高斯 95% 包含系数；6.1 = 固定窗二阶矩杠杆；0.66σ 噪声底；3.1% 容限影响）。
  **B 臂（写时义务四行登记）也 4/4。差值 = 0，A 臂已在天花板。**
- **所以本轮不能声称**"写时义务无用"（没有改进空间），**但必须承认**：
  **抓错的瓶颈是读者的物理先验，不是工作区给的支撑**——至少在"库小、线索同屏、错误是教科书陷阱"时如此。
- **合理推断**：旗舰主张"关联召回帮评审发现遗漏因素"**不是错，是还没被测过**，
  而且这是**第二次**出现"实验与命题不同形"（第一次 P4 语料全 T0/T1，第二次本轮库太小导致取回率指标恒等于 1）。

### ④ 有正向信号、且现已定量（证据中）：可审计性

**已量化**（`e4bp/RESULT-E4bp.md` §7，结构打分器 `audit-scores.json`）：

| 指标 | A 臂 | B 臂 | 倍数 |
|---|---|---|---|
| 抓对率 | 4/4 | 4/4 | 1.0（**同为天花板**） |
| 引用记录条数 | 10.5 | 10.2 | **1.0（引证据的量完全相同）** |
| 工件指纹（sha/版本）绑定 | 0.5 | 6.8 | **13.6×** |
| 显式缺口声明 | 0.8 | 5.2 | **6.5×** |
| 可复算线索（脚本/算法/参数） | 0.8 | 3.8 | **4.8×** |

**B 臂抬高的是下界不是上界**：A 臂工件指纹最多 2（有席位自发引了 deck sha），B 臂**最少 5**。
即：**足够自觉的读者可以自发做到可审计，但义务制把它变成不依赖自觉的下界。**

> 收敛成一句：**写时登记不改变"能不能抓对"，也不改变"引了多少证据"；
> 它改变的是第三方能否复算、缺口是否留下记录、结论能否被追责。**
> 当前门禁考的是**检出率的上界**，设计真正给的是**可审计性的下界**——**目标与尺子不匹配的定量版本。**

（保留的原证据，作为定性佐证：）
- **已证实**：B 臂产出了 A 臂**结构上没有**的东西——逐量定义出处、前提→工件 sha 绑定、同口径声明、
  run 终态声明，以及**显式的"库内无记录"否定**（不确定度缺失、某次首跑终态未知、σ→ε 传递系数缺失）。
  A 臂的结论正确，但是**不可追责的正确**：对的时候说不清为什么对，也不知道自己漏了什么。
- **已证实（反身实例，最有说服力的一条）**：**三个不同席位各自独立发现了我造的案例里 βγ 换算写反**
  （我用了 ε_n=ε_geo/βγ，且 βγ 取 0.4043 而非 0.403340）。
  **我自己两次都写反了同一个常数，作者自检没发现**；是"作者≠复核者 + 逐量登记"把它抓出来的。
  → 这正是用户目标（**可信、可审计**）的正例，而它跟"发现隐蔽错误"**不是同一件事**。
- **合理推断**：值得建的机制是**"审计链完备性 + 缺口显式化率"**，两者**可确定性度量**；
  而"能否发现错误"**不是好尺子**（强读者不需要工作区也能发现，弱读者给了工作区也发现不了）。

## ⑥ E7 更新：检索侧**第一次**拿到方向性证据，但这一票投给**索引层**（证据中，n=1/格）

前两轮 null 的根因是"整库一次性可见 → 取回没有代价"。E7 把代价做出来（40 条库、只许读 12 条），
判读规则**预注册在先**（`e7/PREREG.md`，20:42Z）。三格读数：

| 格 | 索引 | 义务 | 结果 |
|---|---|---|---|
| P-A | 差 | 无 | ❌ **正中植入错误 0.967**（明知越界仍外推，只给 ±5% 主观区间） |
| **T-A** | **好（+一行主题行）** | 无 | ✅ **判对 0.69**（靠主题行锁定三条域外实测，自己算出亏缺单调性；**连现成接管式都没读**） |
| P-B | 差 | 有（取阅计划+四行登记） | ❌ 另一种错 0.38（漏读系数记录；但**它是唯一说清自己缺什么**的样本） |
| P-A2 | 差 | 无（复本） | ❌ 0.966——**读到了接管式并算出了 0.703，却被"最新评审暂缓"劝退** |
| P-A3 | 差 | 无（复本） | ✅ 0.700（取到系数+接管式，自行否决了暂缓口径） |
| T-A2 | 好 | 无（复本） | ✅ 0.69（域外三点 3/3 命中，同样推翻暂缓） |

**合并：差索引 1/3 对，好索引 2/2 对**（n=5，同模型，预算受限）。

三种**不同**的死法（这才是最有价值的部分）：**找不到数据**（P-A）、
**找到记录但被被削弱的二手汇总否决**（P-A2）、**缺系数导致错乘**（P-B）。
而好索引两臂都**摸到了原始数据**，于是**有能力否决那条被削弱的汇总**——T-A2 甚至没读现成的接管式也算对了。

> **索引的真正作用不是"帮你找到答案"，而是"让你摸到原始数据，从而能否决一条被削弱的二手结论"。**
> 这正对上真实样本 E-A1 的形状（E4a 里唯一站住的那件 T3：中间汇总与原始记录方向相反）。
> 而义务（P-B）治的是另一类错（登记/推理），**防不了"该读的那条没读到"**——
> **两类失败要两种机制，不能互相替代。**

命中的预注册分支是 **「T-A 对而 P-B 错」→ 元数据 > 登记**。于是 §③ 的判据要更新：

- ✅ **检索/召回这一侧大概率是对的**——同一案例同模型，**只改"索引给不给一行主题"，
  结果从正中植入错误翻成判对**。这是本项目第一个"改动记录系统的一个属性 → 改变结论正确性"的观测。
- ❌ 但起作用的属性是**廉价元数据索引**，**不是登记义务，也不是对象模型**。
  义务改善的是**自我诊断**（P-B 准确说出"缺 r03/r20/r23，补上就能算"），不是**检索命中**。
- ⚠️ **P-A 的翻车方式值得单独记**：它**知道**自己越界（正文写了"超出段未检验"），
  但没有证据可修正，于是照常外推。**真实世界的翻车不是"没想到"，是"想到了却没去查/查不到"——
  这正是索引该管的，不是类型系统该管的。**

## ⑦ E5：读时对账的**真实能力与类别边界**（已证实，n=9 事件）

通用 claim↔artifact 对账谓词（8 条，零事件特定规则，冻结在先 `FROZEN.txt`）跑 3 个真实包：
**读时检出下界 4/9（可测子集 4/6）**，低于席位的 ~6/9 假设。
我独立复核了最强那一击（真实脚本自称 `unpaired -> abort`，全脚本无 assert/raise/exit——**担保只测量不拦截**），**成立**。

- **能抓的**：包内**自相矛盾**（清单覆盖不足、声明路径悬空、同标签两口径 21 处并存、担保在工件内不存在）。
- **原理上抓不到的**：**跨包/跨版本的前提更换**（配对源不在同一库）、**包内一致但口径本身换了**
  （库里没有互相矛盾的两条记录可对）。→ 这两类**只能写时拦**。
- **成本不对称（E5 真正值钱的数）**：`111 次命中 / 4 件真实事件 ≈ 每件 28 条人工分诊`，
  最严读法下 59.5% 可能良性；而写时代价是**每件 1–3 行声明**。
  **同一个对账机制，放在写时比放在读时便宜约两个数量级，且覆盖更全。**
- **席位那句"需要的是登记义务，不是检索机制"我下调**：前半句的提问方式近乎同义反复
  （"若当时登记了能否避免"对任何未登记错误必然为"能"），后半句**被 E7 反驳**
  （P-A2 读到了记录仍被二手汇总否决，索引才救得回来）。

## ⑧ 案例库独立复核的结果：我的档位判定 **2/2 被推翻**，但结论变得更锐利

  并给校验器补上**第 ⑨ 道门：物理换算方向自洽**（负例可 FAIL）。
  → 这本身就是一个范例：**同一类错误，写时机验比读时人审便宜。**
- **自伤泄漏**：C2 的「±0.02%」与另一条「±1.1%」同条件矛盾（可被最低档匹配器直接抓到）；
  且 `r07`「同一随机种子序列」推翻了答案钥匙自己的**独立性**算式。已修。
- **档位改判**：**V2 由 T3（共变混杂）改判 T4（前提/适用域越界）**。
  复核的甄别很硬：**唯一致错路径是漏召回"适用域上限 W_max=2.40"那条记录**；
  只漏"接管式"的人仍可从三条实测点**自行重拟合**出指数而修正或挂起；
  而"固件共变"**已被登记、且已被 A/B 对照控住（差 0.4%）**——它只是那条"暂缓采用"决议的**说辞**，不是混杂。
- **我的档位判定被推翻的记录：连续两案 2/2**（E4a 的 T4 33%→11%，V2 的 ④→⑤）。
  **纪律结论：档位判定不得由作者出**，必须是流程里的独立席位，且用"按可检性来源"的梯子而非物理深浅。
- **对第一轮 null 的影响（变弱）**：C4 在当前状态下其实是伪装的最低档题，C2 有泄漏，
  所以"自由记录臂 4/4 全抓到"**除了整库可见之外还有第二个原因——案例本身偏易**。
  这不改结论方向，但让那轮 null 的解释**更不完整**（也更说明"难度要靠检索代价做出来"）。

**变得更有用的东西：三条独立线索指向同一个错误类别，而解法仍然不是图。**

| 线索 | 指向 |
|---|---|
| E4a 里唯一站住的高档事件 | 适用域越界 |
| E5 读时对账漏掉的两件 | 前提更换 / 口径换代（**配对源不存在**） |
| V2（唯一有判别力的案例，经复核） | 适用域越界 + 已记录的接管关系未采用 |

→ **承重的错误类别是"前提/适用域的可召回性"**（这在 v3 里对应前提图，看起来像支持图）。
**但 E7 显示救回来的是"每条记录一行主题"，而复核进一步证明"能摸到原始数据"比"有现成的关系式登记"更抗失败**
（漏掉登记式的人还能从实测点自己拟合出来）。
**所以：这一类错误确实最贵，但本轮测到的解法是"可发现性"，不是"图遍历"。**

## ⑨ E8 混库复现：索引问题**无效**（我的装置缺陷），但抓到一条更重要的风险

预注册规则命中 **R2（两臂都判对 → 不得声称索引普遍有益）**，但 R2 不能干净收下，因为自检发现
**索引的 `t` 字段把项目身份白送了**：靶案是单日会话，`t` 单字段即可 **12/12、100% 纯度**分流（已写成
`e8/index-leak-check.py`，任何贫/富索引对照**必须先过这道自检**）。所以 E8 对索引问题**无效**，
**也不得读成"索引没用"或"设计无用"**。

**E8 真正的产出是一条被预注册抓住的风险（R4）**：好索引臂把**别案的数值**串进靶案论证——
它取阅了另一个仪器案例的结论记录「空间电荷使发射度 0.489→0.550，+12.4%」当作靶案的物理上限；
而**那个数在它自己家里已被判定"约 3.1% 属数值容差、对照失效"**，**搬运时那条例外记录不会跟着过来**。
差索引臂跨案取阅 0/11，好索引臂 1/12。

> **更丰富的元数据同时提高跨项目串用数值的概率。**
> 所以「加索引」不充分：**数值必须与工况/适用域同生共死**，否则索引帮倒忙。
> 这修正了我此前的排序——**索引层与适用域登记不是两件可分开的事，后者是前者的安全阀。**

**另有两点**：① 两臂**判定相同但不确定性表述不同**（好索引臂识别出 β 与光斑同源污染，把区间从
+3~+6% 放宽到 −2%…+5%）→ 检索条件也许不影响"对不对"而影响"**校准得好不好**"，
这是比检出率更有希望的因变量。② **作者钥匙第二次算错**：杠杆 (a²/3)/σ² 随光斑收窄放大 25%，
**必须在末档用末档 σ**（12.9% 而非我写的 8.8–11.2%）——**两个盲席位独立发现，独立复核席也漏了**。

## ⑩ E9：修掉泄漏后索引效应出现了，但**不在"对错"这一列**——并给出第一条可机验的设计要求

自检通过（`t` 只能命中 3/12、纯度 50%）后重跑混库：**两臂判定相同（都判"归因不成立"）→ 检测率仍是平手**，
但证据归属差出四倍：

| | 取阅命中本项目 | 写进结论的定量输入来自别的项目 |
|---|---|---|
| 差索引 | **2/11 = 18%** | **7/7 = 100%** |
| 好索引 | **9/12 = 75%** | 2/9（且都带"工况未知"标注） |

差索引臂的整套论证——"算法台阶 −3.1%""容差台阶 ≤−3.1%""Δ0.040 是空间电荷全区间的 66%""当日流强 1.19 mA"——
**四个数分别来自另外三个案例的仪器**，而它**始终没读到靶案自己的证据**。
结论写得完整、每条都带记录 id、算术全对，**但没有一个数属于被审查的那次扫描**。

**新失败模式：伪造的定量性。** 检索失败不表现为判错，表现为**用邻近项目的数搭出看似定量的修正**。
它骗过检测率（两臂同判）、**也骗过引用计数——而且奖励它**（差索引臂引了一堆 id）。
**据此撤回我把"引用记录条数"当正向指标**：两臂本就同分（10.5 vs 10.2），E9 进一步显示**引用得多可以是串案的症状**。
另外：两臂提示词里都**明文警告过**"不要把别的项目的数当本项目依据"，仍然全借——**散文级提示不是控制**。

> **第一条正向的可机验要求：审计链必须查"出处的适用范围是否与论断一致"**
> （项目 / run / 工况 / 适用域），而不只是查"这个数有没有出处"。
> 它正好落在 E7/E8 两条结论的交点上（可发现性 + 数值与适用域同生共死），
> 而且**反过来给写时义务换了个理由**：不是为了帮思考，是**为了让这个谓词跑得起来**（需要 `(值, 记录 id)` 对）。

## ⑪ 重造四案 + AB3/AB4：唯一稳定的效应是**方差**，不是正确率

按用户四条意见重造后（每 N 只一点、2.97 π-mm→1.61 mm 且删同输入重算、证据拆四种形态、删容差扫描），
独立复核席仍判**三案需修后跑**（又抓到 6 处钥匙错与两处自伤，全部已修；
其中最漂亮的一条：**五点全单调的收敛扫描在纯噪声下概率仅 0.8%**，既泄方向又自相矛盾）。
修完档后四案恰好覆盖 v3 四个子系统各一个（`negative-state / caliber-registry / design-record / premise-graph`）。

**AB2 A 臂**：4 案 3 破 1 败——三案的席位**自带**了我删掉的中间量（1/√(2N)、杠杆、容限影响），
所以这类案例**测的是模型物理先验 + 取阅运气，不是登记设计**（不得把 3/4 通过当成对设计的肯定）。
唯一失败案暴露 **半提示比无提示更危险**：席位没读任何分析记录，仅凭两条"现实质感"记录就判"不成立"，
然后**编造 δ 填定量缺口**，符号相反。

**AB3** 一度给出本项目第一个干净对照（A 两复现反号、登记臂与索引臂同时算对 +34.4%），
但**AB4 用修后库重跑，A 臂自己取满 5/5 线索并算对 → 对照作废**（预注册写明的退路被触发，照此执行）。

> **并表后能站住的只有一句**：干预格关键记录命中率 **5/5、5/5、5/5**；A 格 **0、2、2、5**。
> **所以设计主张要改写成："索引/登记压低取阅方差、消除尾部失败"，而不是"提高正确率"。**
> 尾部形态才是真正的事故：**漏读 → 凭怀疑编出一个带区间的错数**。
> 这也解释了此前所有全可见 A/B 为什么全部撞天花板——均值本就够高，值得救的是尾部。
> 证实它需要 A×4 / B×4（比"命中率<满"与"反号率"），8 席，待批。

## ⑫ AB5 开放式推进 + 两套防漂移机制落地

**实验**：同一批四案，**不给审查式提问**，只给数据与交付要求（"给出结论 + 可支撑到何种工程决定"），预算硬约束。
结果 **4/4 自行破题、零复述** → 审查式提问不是主因（G1 不成立，G2 命中：这四案对当前模型偏易）；
预注册期待的"把库内错误结论写进交付物"**没有出现**——这是登记在案的**负结果**（n=1/格，不外推为"不会发生"）。
新假设（H-AB5）：**起作用的可能是一句交付模板**——要求交付物自带适用边界；须做 2×2 才能归因。

**两套防漂移机制（由用户批评直接催生，均已落地并当场咬过我）**
1. **语义监督 = `CLAIMS.md` 效应声明台账 + `check-claims.mjs`**。规矩：任何出口的主张必须先登记并挂接自己的实验设计。
   第一跑就**拦下我上一条汇报的原话**（"压低取阅方差、消除尾部失败"按 MEASURED 登记 → 5 条不合格：
   无预注册 / p=0.143 / design 含"事后" / 跨用途并池 / 多格未声明对照）。现存 9 条主张，**只有 1 条够格 MEASURED**。
2. **形式化推理检查 = `validate-cases.mjs` 第 ⑩⑪ 道门**。
   ⑩ 正文引用日期不得晚于记录时间戳；⑪ 被赋数值的自造量必须定义（**裸 `=` 不算定义**）。
   两道的缺陷都是**开放式席位抓到的，独立复核席逐条复算物理时漏过**（因果序不可能 + `resid_dark_share` 无定义）。
   后者导致**同一机制三个读者三种杠杆**（4.70 / 6.09 / 7.59）→ "答案可推导"≠"能推到唯一数"；
   列定义写死后钥匙第三次改：**+6.3%**（旧 +4.4% 与复核席 −11.2% 同时作废）。

**还自查出一项贯穿性装置缺陷**：旧取阅工具**从不拦截预算**（只打印硬编码"预算 12"），
所以 E7/E8/E9/AB2/AB3 的"预算受限"实为**软约束**（席位自报未超、日志可核，但约束强度需打折）。
现 `tools/peek.mjs` 硬约束 + 非法 id 不计次，实测 9 次尝试只放行 8 次。

## ⑬ ARM1：最小臂 vs 全量臂（真实轨迹案例）——**你的话第一次被可复跑地部分证实，也被量出了边界**

13 条条目全部取自真实 jKDesign 轨迹（`REALTRACE-1.md`，每条带 文件:行号）。三臂：
**A** 真实 run 产物零改造 / **A+** 最小臂按规约做满 / **B** 全量 HSR 记录面。7 个谓词只从 value 计算。复跑 `node armtest/run.mjs`。

| 臂 | 谓词可运行 | 裁决正确 | 写时代价 |
|---|---|---|---|
| A 真实产物 | 11/13 | 9/13 | 0 |
| **A+ 最小臂做满** | — | **11/13** | ≈0–2 行/案 |
| B 全量记录面 | 13/13 | 13/13（**可表达性上限**） | 2.0 行/案 |

**A+ 漏的只有 2 条，且都正好落在你要的那一列上**：
① 同一观测点互斥测量值→禁止升级为"已验证"（H2VN 把 1.83/2.107/118.74 的跳变写成"已验证不可达"）——
最小臂三条义务**没有测量级对象槽位**；② 跨 run 反例可见性（H2VN 的"不可达"早被 M3RD 解析落 M 1e-11 证伪）——
最小臂**没有跨面引用槽位**（而 B 臂按 HSR 自身 SD-20 也只能**标记**，仍需人裁）。

**按 C-12 预先写下的裁决规则**（「最小臂能否支撑全部已声明谓词运行；不能 → 过剩判断不成立」）：
**"HSR 相对最小臂冗余"的指控不成立。**
同时必须说出难受的一半：**11/13 的保护价值来自几乎免费的最小臂**，
HSR 的不可替代增量集中在 **2/13**——但那 2 条恰好是"判断'不可能'对不对"的两根柱子。
→ **预算顺序：先把最小臂做满，再建测量级对象与跨面引用。**

**第二条独立证据（按你的裁决改写）**：文本层谓词把 L9T4 的「**未宣布**目标不可达」误报成不可达宣称（否定盲区），
而类型化主张按 `kind` 天然放行 `escalation` / `falsification-report`。
⇒ 受管对象必须是**出口的判断**（不可达 / 极限 / 跳过复核：须带 适用域+已排除备选+判据指纹+基线参照，缺则阻断出口），
**不是行动的选择**（选哪条分支、α≈1.32 还是 α≤1 一律放行）。**L9T4 是正向证据**，我原先"该有阻断权"的说法对象错了。

**这张表证不了的那件事**：A+ 的 11/13 假设登记被"做满"。真实写入能不能做满，需要**写时双臂实验**——
这是下一个该跑的实验。

## 三件按性价比排序该做的事（E5 后再排，E8 微调）

1. **先做索引层 + 写时三条声明，两件一起做**（E7 + E5 的合力）：
   每条记录一行主题 + 量→定义出处注册 + 适用域登记（**索引**，治检索），
   与结论侧 1–3 行声明（口径 / 前提+工件版本 / 终态）（**义务**，治覆盖面与成本）。
   **E5 的成本不对称是"写时"最稳的论据；E7 的翻转是"索引"最稳的论据。**
   **E8 的约束（安全阀）：可发现性必须与适用域绑定**——数值脱离工况被搬运时，
   索引反而把别案**已被判定失效**的数值送进本轮论证（实测 1/12 次取阅）。
   两者都**不需要五类对象，也不需要图**。
2. **读时对账降级为兜底，不作门禁**：E5 证明它有用（4/9 且含扁平 linter 看不见的类别），
   但每件 28 条分诊成本 + 59.5% 良性上界意味着它**必须配分诊通道**，不能当红绿闸。
   验收指标改成：①**审计链完备性**（已测 13.6×/6.5×/4.8×）②**缺口显式化率**③**预算受限取回率**（E7 装置）
   ④**适用范围一致性**（E9 新增，本项目第一条可机验谓词：数值的出处是否与论断同项目/同 run/同工况/同适用域）
   ⑤**校准质量**（区间是否有依据、是否声明未控混杂、是否给出判别实验；E8/E9 显示判定相同时这一列仍有差异）。
   **禁用"引用记录条数"作为正向指标**（E9：引用得多可以是串案的症状）。
   **强制加"仅索引"与"扁平谓词+通读"两条基线**，且**任何贫/富索引对照必须先过 `e8/index-leak-check.py`**
   （E8 就因索引 `t` 字段可 100% 分流靶案而整轮作废）。
3. **先做重叠评估再写内核**：`real2sim-*` 技能族与宿主 Cordis 的重叠没算过账（`BOUNDARY-REUSE.md`）。
