## E0：双图谱的实测优势能否被更廉价的方法复现

**三个独立结论**（复跑命令见下，全部数字为实跑，不采信任何既有报告）：

1. **既有四臂读数可独立复现**：`rawScan 4/7 (q7/n31)`、`inferenceOnly 3/7 (q5/n62)`、
   `associationOnly 4/7 (q1/n42)`、`bothAlternating 7/7 (q6/n104)` —— 与
   `../v3-semantic-poc/REPORT-P4.md` 逐字一致。**这是对该报告的独立验证，不是它的重复。**
2. **对照臂缺失（本区的主结果）**：一个约 60 行、**单趟扫描、零图、零多跳、零 LLM** 的扁平确定性
   一致性检查器，在同一语料上 **7/7**。即：为「双图谱是否有增益」这一主张提供全部证据的语料，
   其增益可由一组结构性谓词在扁平信封上完整复现。既有实验里**没有任何一臂是这个基线**——
   `rawScan` 被实现为纯文本扫描（无完整性谓词），因此它的 4/7 不构成对照，只构成稻草人。
3. **语料自身泄漏答案**：4 条植入缺口的**说明文字写在刺激 payload 正文内**（例：
   `RUN-AB-B:3` 的 claim 含「（GAP-01：based_on 含不存在的 seq 99 → 断链）」）。实测剥离标签后
   **四臂读数完全不变**——说明这四臂是结构判定、不受文本泄漏影响（内部效度保住）；
   但这直接否决了**任何以该语料做的人评或 LLM 席位实验**（含 #10 §4-P4 计划中的人工标注 A/B，
   以及本区 E1–E4 的原始素材）：**不脱敏不得开跑**。

**证据边界（不得越界声称）**：

- 该语料的 7 个缺口**全部是完整性缺口**（断链、无锚、指向不存在、无支持关系、依据落在失败 run、
  共用 deck 无连接），**没有一个是语义缺口**。因此 E0 证明的是
  「**这套语料测不出双图谱的设计意图**」，而**不是**「双图谱无价值」——
  #10 §4-P4 原文要测的是「帮评审发现**可能遗漏的因素**」，那类缺口必须语义化才能成立。
- 语料 31 事件 / 7 文件、由 V3 作者自建，样本量 7；结论不外推到真实语料。
- 扁平 linter 的 7 条规则是**本区作者**按 PoC 的 SPEC 写的，未与 V3 团队共同设计；
  其可维护性（规则随字段增加而膨胀）未测。

## 席位污染控制（E1–E4 强制前置）

实测结论：**`git worktree` 不防偷看**——worktree 与主仓共享 object DB，席位内
`git log --all` 可见全部提交与结论、`git show <其他分支>:<文件>` 可直接取答案、父目录可达；
且 `workspace-write` 只限写不限读，**全机可读**。因此盲测的强制前置是：

1. **净室**：`git archive` 导出（无 `.git`）→ 解包 → **物理删除**答案面 → 校验残留为 0 才准开跑；
2. **脱敏**：刺激材料正文中的任何结论性标注（缺口编号、"→ 断链"这类判语）一律剥离，剥离计数入账；
3. **canary**：投放只含诱饵的伪答案文件（`GAP-99` / `AUDIT KEY`），席位输出若引用即整次作废；
4. **最优解是答案不落盘**：构造类案例的答案键只存在于评分侧内存上下文，净室内无可偷之物；
5. docker 只读容器当前不可用（无权限），故**不声称硬隔离**，只声称「泄漏可检测 + 无意泄漏已被切断」。
