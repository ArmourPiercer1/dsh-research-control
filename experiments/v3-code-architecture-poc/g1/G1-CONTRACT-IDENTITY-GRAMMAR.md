## 1. IG-1 `space_id` 文法（我方新命名；本体在此落死）

### 1.1 形态（规范句 + 机读块）

「`space_id` 是宿主登记面签发的**不透明小写 ASCII 字符串**：字符集、上下界、比较规则以本
机读块为准；文法合法 ⇔ 逐字符满足字符集，**不做任何规范化后再比较**（IG-1.2）。」

```
<!-- IG-1 GRAMMAR-BEGIN
SPACE_ID_GRAMMAR=^[a-z0-9][a-z0-9._-]{0,63}$
SPACE_ID_LEN_MIN=1
SPACE_ID_LEN_MAX=64
SPACE_ID_CHARSET=ASCII 小写字母 a-z | 数字 0-9 | 连接号 - | 点 . | 下划线 _
SPACE_ID_FIRST_CHAR=必须为 a-z0-9（排除 . / .. / 首点名 / 全点名的语法途径）
SPACE_ID_RESERVED_WORDS=default | assembly
SPACE_ID_COMPARISON=逐字节等值（禁 case-fold、禁 NFC/NFKC、禁二次 percent 解码后再判等）
IG-1 GRAMMAR-END -->
```

- **字符集**：`a-z`、`0-9`、`-`、`.`、`_`。首字符必须字母或数字——`.`、`..`、隐藏文件名式
  首点名在**文法层**即不可能（G-15 同族：非 ASCII、空白、控制符、超长一律文法非法）。
- **上下界**：1 ≤ 长度 ≤ 64。64 与 SF-20「长度上限 64 字符」（G-04，条件式）同界；下界 1。
  上界是**硬约束**（超长即形态非法，不钳制、不截断——SI-50「超上限拒绝而非钳制」同向）。
- **大小写**：字符集**排除大写**——这不是「不区分大小写」而是「大写形态非法」：登记域从根上
  不存在折叠歧义区（文件系统/宿主注册表按大小写敏感性各异的场景里，`Alpha` 与 `alpha` 永远
  不会是两个候选身份）。比较一律逐字节；**禁任何大小写折叠**。
- **Unicode/同形异码点**：非 ASCII 一律文法非法 ⇒ 全形字符（`ａ`）、NFC/NFD 分解式、组合音标、
  bidi 控制符、四字节 emoji 全部在文法门外，**永不进入比较域**——规范化问题被字符集裁决消灭，
  而不是靠「先规范化再比」维持（后者会把归一化器变成第二判据面）。
- **百分号（框层与值层两分）**：`%` 不在字符集 ⇒ **值**含百分号（一次或多次编码形态）对文法
  一律非法；百分号编码只是传输通道的**框层形态**——通道框层解码至多一次，解出的产物即值本体、
  必须重过同一文法（IG-4 步骤②），**解后仍含 `%`（多重编码）即拒**；**机制面自身从不解码**
  （IG-1.2），机制入口收到含 `%` 的串按形态非法拒（纵深双闸，同形形态码）。

### 1.2 编码与规范化（一条总判据）

「机制面**零规范化**：不 NFC、不 NFKC、不 casefold、不解 percent、不 trim 空白。合法集 = ASCII
闭集 ⇒ 对合法值所有上述变换都是恒等；对非法值任何上述变换都不得使其『变合法』。规范化义务
全部推给传输层入口（IG-4 步骤①②），且解后必复验——**校验点顺序本身就是判据**（IG-4）。」

### 1.3 前缀与保留字

- **无类型/路由前缀**：`space_id` 不携带类别、路由、物理位置前缀（D1-a「不得编码空间名或任何
  路由事实」G-13 对空间自身的推论：它是身份，不是路由提示）。
- **保留字封闭集 = {`default`, `assembly`}**：`default` 保留给宿主「隐式缺省空间」哨兵语境，
  防显式创建的空间与隐式缺省值在呈现/迁移面不可分辨；`assembly` 与装配作用域值 `scope='assembly'`
  同名会污染审计行与运维工具里的「作用域 vs 空间」判别。**新增保留字 = 冻结面变更**（IG-6）。
- **与物理 ns 的关系（G-15 先例，同型不借用）**：IG-1 文法与 RL-4 门 3 `NS_SHAPE`
  （`^[a-z0-9][a-z0-9._-]{0,63}$`）**逐字符同型**——这是刻意复用同一把尺子（一份语料两处测）；
  但**注册域分离**：`space_id` 由宿主登记、`storageNamespace` 由插件清单在**空间内**注册
  （`capabilityOfNs` 唯一性 = 空间内判据，RL gate 4）。两条禁令：
  ① `storageNamespace` 不得由 `space_id` 派生（拼接/前缀/哈希皆禁）；② 重定位改 ns（RL-5.1）
  **永不**改 `space_id`——空间是文件/事务边界（P1 G-18），ns 是空间内位置键（RL-6.1）。
- **`space_id` 不进任何标识字符串**（P1 冻结句 G-18；SF-25 同向 G-06）：oid/record_id/ns/引用
  串的合法形态中都不得出现空间分量——空间归属只存在于 Directory 行（G-24）与 SpaceContext 路由。

### 1.4 生成算法责任者

「`space_id` 由**宿主登记面**（装配根一侧：空间创建 = 建库文件 + 宿主注册表占名的同一动作）
签发；**机制不发号、不定名、不建议命名法**（Kernel 业务无知的身份面推论）。机制只做三件事：
文法校验（构造期，IG-4⑥）、出生绑定核对（IG-1.5）、比较等值。」宿主登记面同时承担
「同一宿主域内唯一性」判据（碰撞在宿主注册表即拒，机制不见此码）。

### 1.5 冲突与重用政策（出生绑定）

- **出生绑定**：空间库首次写入时，`space_id` 与该库文件绑定（现状载体 = `ledger.space` 列首行
  事实，G-22 现表形；正式载体 G2 DDL，本契约不写 DDL）。此后以**不同** `space_id` 打开同一库
  ⇒ `SPACE_FROZEN`（既有码既有语义「试图改变已固定的空间」，G-23；零写、零迁移、不销毁原字节）。
- **永不复用、永不重新解释**：空间退役后其 `space_id` 不得授予新空间（ID-01「永不复用、永不
  重新解释」G-01 的**我方推广命名**——ID-01 原文只裁对象 id，此为本契约层扩展，如实标注）；
  理由同族：复用会让旧 ledger 行、旧审计、旧引用在读者面换主。
- **不存在跨空间迁移**（ID-02 原文 G-02；RL 重定位搬的是能力路由的**空间内物理 ns**，不跨空间，
  RL §6 冻结判据）。

### 1.6 可打印与日志安全

「合法 `space_id` = 纯 ASCII 可打印、无空格、无分隔符、无控制字符 ⇒ 可原样入日志行/JSON/CSV，
无转义歧义、无注入面。拒绝响应与错误日志**不得逐字回显畸变候选**（候选可含控制符/同形字符/
超长串，回显 = 日志注入与放大载体）：只回显 `{shapeClass, length, digest(sha256 前 12 位)}`。
现状 `kernel.ts:1276` 的 detail 逐字回显（G-22）在 IG-4 文法闸门**之后**变得天然有界（§7 O-2
登记实现批小改）。跨空间方向的呈现纪律不变：『呈现形态不携带对方空间标识』（G-19）——
`space_id` 对本空间上下文合法可打印，**跨空间错误体**（`CROSS_SPACE_REFUSED`/`NOT_FOUND_IN_SPACE`）
的 detail 不得携带任何其他空间的标识或其派生量（D1-d 五类载体同规）。」

### 1.7 是否内嵌空间/类型信息（明写）

「`space_id` 自身的**所指**就是空间，故『内嵌』问题对它取如下形式：它**不得内嵌任何路由事实**
（物理文件路径、`storageNamespace`、插件/宿主租户标识、机密、时刻、序号语义）。它是不透明名，
Directory 行与 SpaceContext 是唯一路由权威（G-13/G-24）；任何把 `space_id` 当路由提示使用的
代码路径 = 第二权威索引嫌疑，撞 D1-b 三禁令（宿主索引『不作授权判据』同族）。」

## 2. IG-2 `record_id` 文法（V3 侧车面；我方新命名）

### 2.1 形态（规范句 + 机读块）

「`record_id`（非对象记录的自身标识：`declareRecord` 声明形记录、机制台账记录 `RPT-`、扩展记录
`FR-`、挂载登记 `FM-`、重定位账 `NSR-`）是**不透明 ASCII 字符串**，逐字节判等；`rec:` 是引用
**方案前缀**（scheme），不是标识的组成部分（IG-2.4）。」

```
<!-- IG-2 GRAMMAR-BEGIN
RECORD_ID_GRAMMAR=^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$
RECORD_ID_LEN_MIN=1
RECORD_ID_LEN_MAX=64
RECORD_ID_CHARSET=ASCII 字母大小写 A-Za-z | 数字 0-9 | 连接号 - | 点 . | 下划线 _
RECORD_ID_FIRST_CHAR=必须为 A-Za-z0-9
RECORD_ID_RESERVED_PREFIXES=RPT- | FM- | FR- | NSR-
RECORD_ID_COMPARISON=逐字节等值（禁 case-fold、禁 NFC/NFKC、禁二次 percent 解码后再判等）
RESERVED_PREFIX_MATCH=逐字节前缀 ∪ ASCII 大小写折叠前缀（两形都算命中）
REC_SCHEME_GRAMMAR=^rec:[A-Za-z0-9][A-Za-z0-9._-]{0,63}$
REC_SCHEME_TOTAL_LEN_MAX=68（"rec:" 3 字符 + 标识 ≤64）
IG-2 GRAMMAR-END -->
```

- **字符集含大写**（与 IG-1 相反方向的裁决，理由如实）：机制既有发号形态 `RPT-`/`FM-`/`FR-`/
  `NSR-`（G-16/G-22）是大写前缀，文法必须容纳既成事实且 SF-20「大小写敏感」（G-04，条件式）
  同向 ⇒ 大小写并存 + **逐字节判等**；折叠歧义区由 IG-2.2 的保留前缀双检封闭。
- **冒号不在字符集** ⇒ 任何 `record_id` 都不可能含 `:`；`rec:` scheme 因此**无歧义**（不需要
  「scheme 后第一个冒号」之类的解析规则），双 scheme 自包含串（`rec:rec:x`）自动文法非法。
- 上下界同 IG-1（1–64，SF-20 同界）；`rec:` 串总长 ≤68。

### 2.2 比较与规范化（与 IG-1.2 同判据 + 一条前缀双检）

- 判等/唯一性比较一律**逐字节**；`Abc-1` 与 `abc-1` 是**两个不同**标识，允许各自首次声明并存
  （T-P4）。文法与比较**不做** casefold/NFC/NFKC/percent 解码（机制零规范化，IG-1.2 同句）。
- **保留前缀匹配是双形的**：逐字节前缀 **∪** ASCII 大小写折叠前缀——`RPT-1`、`rpt-1`、`Rpt-1`
  全部命中保留（仿冒面在折叠等价类整类关闭；「大小写敏感判等」与「保留域按折叠类设防」不矛盾：
  后者只**扩大拒绝**，不制造判等混淆）。全形仿冒 `ＲＰＴ－1` 在文法闸先拒（非 ASCII），
  **顺序保证**文法闸先于保留前缀闸（IG-4③→⑤），故保留闸的入参恒为有界可打印串（回显安全，
  IG-1.6 同理）。

### 2.3 保留前缀封闭集（承接不新裁）

「声明类通道（`declareRecord` 显式 `recordId`、任何未来显式发号入参）携带保留前缀（按 IG-2.2
双形匹配）⇒ `RECORD_ID_RESERVED`（D-21 既有码既有语义 G-22；FM-1.2 已把 `FM-`/`FR-` 入集
G-16；`NSR-` 已由 RL §11.4 入集）——本契约把封闭集**登记为** `{RPT-, FM-, FR-, NSR-}` 并施加
双形匹配，**不新裁前缀全集语义、不开放域保留申请**：那是 G1-LINK-01 问 ④ 的既有去向（G-27），
其任何扩员按 IG-6 冻结义务走。`src` 现状常量 `RESERVED_RECORD_ID_PREFIXES = ['RPT-']`（G-22）
是实现批扩员点（§6.2 回填清单 R-④）。」

- **引用 ≠ 声明**：引用已存在的保留前缀标识（record-ref、`rec:` 串）**不受**保留闸约束
  （D-21 原语义 G-22「引用已存在的 RPT-* 不受影响」）——保留闸只站在**首次声明**通道上。

### 2.4 `rec:` 引用方案（形态义务）

- 非对象记录的**字符串引用**形态 = `rec:<record_id>`（G-05 同向；本面条文非借道）。方案名是
  固定小写字面量 `rec:`；大小写变体 `REC:x`/`Rec:x` 文法非法（scheme 不入折叠等价类——与保留
  前缀双检相反方向的理由：保留双检只扩拒绝面，scheme 折叠会**制造**新合法形态）。
- `rec:` 串**不得出现在对象引用槽位**：对象引用槽只接受 `ObjectRef{oid}`/`RevisionRef{oid,revision}`
  形状（P2 G-18）；`rec:`/`FR-…` 进端点/正式声明槽 ⇒ 领域契约拒（FM-1.2 G-16；RF-05/06 对象化
  是唯一合法路径，不放宽端点类别）。机制责任 = **不把 `rec:`/FR 标识投进任何对象引用解析器**
  （解析器入口断言级拒绝，T-N6）。
- `revision` 不是 `rec:` 的组成部分（记录无修订轴，声明即首次；`RPT-` 报告的「重检 = 新报告」
  由新 id 承载，C11 既有事实）；精确记录引用 = 裸 `rec:<record_id>`。

### 2.5 生成算法责任者（两轨）

| 轨 | 发号者 | 形态 | 唯一性判定点 |
| --- | --- | --- | --- |
| 机制轨 | 机制计数器（`RPT-<seq>` 先例 G-22；`FM-`/`FR-` 同族 D-21；`NSR-` RL §11.4） | 前缀 + 十进制计数（seq 族单调） | 发号即唯一（计数器）；声明通道不能预占（D-21 实测教训：预占可预测 seq ⇒ 阻断他人落库，READINESS D-21 行 RE 段） |
| 领域轨 | 调用方经 `declareRecord` 显式声明 | 满足 IG-2 文法 + 非保留前缀 | 首次声明唯一（`records` 表逐字节 UNIQUE，G-22 现状载体）；碰撞 ⇒ `RECORD_ALREADY_DECLARED` |

「文法**不强制**领域轨自带域名前缀（现状即无）；域保留前缀申请 = G1-LINK-01 ④（G-27），
落地前领域轨共用语料、靠逐字节唯一性互斥——这是**如实登记**的弱点，不是已裁的安心。」

### 2.6 冲突与重用政策

- **碰撞**：同空间内逐字节同名再次首次声明 ⇒ `RECORD_ALREADY_DECLARED`；跨空间同名是**不同
  键空间**（记录标识唯一性 = 空间内事实，ID-02 单归属推论 G-02）。呈现纪律：碰撞拒绝与
  「不存在/无权」**同形**（D1-a 验收列「oid 冲突拒绝与 D1-c 同形」G-13 的记录面同款——detail
  只含调用方自带的 `recordId`，不追加任何存在性判别；T-P8）。
- **重用禁令**：一经首次声明，标识**永不复用、永不重新解释**（ID-01 承接 G-01——记录标识域
  本就在 ID-01/ID-08 语义射程内，此条不算推广）；append-only 面本就无删除通道，「退役后改名
  再发」无机制路径。`RECORD_UNDECLARED` 的引用目标从未声明 ⇒ 对该名首次声明合法（不是重用）。

### 2.7 可打印与日志安全

同 IG-1.6 逐句适用（合法集同样是 ASCII 可打印闭集；畸变候选不逐字回显；跨空间错误体不携带
他空间标识）。附加：机制发号 id 单调可预测（`RPT-<seq>`）是**已登记事实**（D-21 攻击面经保留
闸收口），可预测性**整改**不在本面（属 D-21/E-01 既有裁定面），本合同只保证：文法合法 ⇒
id 可安全入日志，文法非法 ⇒ 在任何回显点之前已被拒。

### 2.8 是否内嵌空间/类型信息（明写）

「`record_id` **不得内嵌**：空间名/`space_id` 分量（D1-a G-13）、对象 `kind`、载荷内容哈希
（禁内容寻址身份，G-04 同向）、时刻/序号之外的隐藏语义、任何路由事实。保留前缀是**命名隔离
域**（谁发号），不是科研类型标签——前缀不承载语义、不参与任何读判据（G-07 原则的本面自立句）。
挂载/扩展双身份纪律承接 FM-1（`FR-` 不冒充科研对象 ID，G-16）；文法层面 `FR-1` 与 `abc1`
只是两个字符串，分类纪律在 FM/领域契约层，不在字符集层。」

### 3.2 形式闸 vs 语义解析（一条分界线）

- **oid 卫生文法**（引用面准入）：`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`——与 IG-2 同族但**只作
  卫生闸门**：防控制符/超长/冒号串进解析器、SQL 面与日志面。卫生闸**不授予** oid 任何语义，
  也**不判**「是否含空间分量」（不透明 ⇒ 字符串层判不了，判据只能在**发号侧**：正式发号函数
  禁止把空间名/路由事实拼进发号串——T-P7 的断言形）。
- **既有夹具形态不回迁**（C2 G-14/G-21）：`OBJ-<space>-<n>` 命中卫生文法，存量判绿；
  IG-3.2 的发号禁令只约束**正式新库发号**（G2）；oid 发号算法本体（随机后缀 vs 加盐计数）
  属 G2 DDL 批 + D-12/E-01 复裁定边界，本契约钉「无空间分量、无内容寻址、不透明不解析」三禁。
- **解析责任单点**：所有「oid → 归属行/物理 ns」的解析只有 `routeNs` 一条判据函数（P3 G-18，
  读写共用，禁复制）；任何旁路（自行 split oid、按前缀猜 kind、按串长猜空间）= 形态非法 +
  第二权威嫌疑（D1-b）。**精确引用不漂移**：`RevisionRef` 一经写入，后续修订不得使其重解析
  （ID-04 G-03；解析器对同一 RevisionRef 的历史求值必须可复算）。

### 3.3 跨空间引用与跨平面引用（首版不合一）

- **V3 首版不存在跨空间引用面**：任何字符串都无法表达「指向另一空间的对象」——`space:obj@rev`
  形态入口即拒零残留（D1-a 验收列 G-13；`:`/`@` 均不在卫生文法字符集，形态闸门自然拒，T-N7）；
  机制 Port 入参**没有 space 槽位**，修订类携带 space_id ⇒ 入口即拒零残留（SS-10/SI-10 同向
  G-08；宿主工具面若收 `space_id` 入参，只允许作**与可信上下文比对**的意图声明，不等值 ⇒ 拒，
  IG-4④；幂等键的 space 分量取可信注入值——X-1 既有裁决，不重开）。
- **合法空间上下文比对**：合法 `space_id` 值但 ≠ 当前 Kernel 绑定空间 ⇒ `CROSS_SPACE_REFUSED`
  （既有码 SP-04 语义 G-23），且与「目标不在本空间」**完全同形**（同码同 detail；不得把他空间
  存在性编码进状态/detail/时延，SI-20/SI-22a 条件式同向 + D1-c 已裁同形）——「跨空间读取没有
  代码路径」五出口纪律继续成立（G-19）。
- **跨平面（V1↔V3↔HSR）**：首版**不合一、不互推**（X-8）；连接仅 HSR 侧 `external_citations[]`

  G-10）；V1 前缀注册表 / HSR `HENT-…` 形态 / 本面 `rec:` 三套词汇互不流入对方解析器。

## 4. IG-4 传输面：校验点顺序与拒绝码（封闭集零扩张）

出现在 **header / query / tool 参数**的 `space_id`、`record_id`、`rec:` 串、oid 引用串，一律按
下列序检查；**顺序本身是判据**（交换任两步都有一步被削弱：③先于⑤否则保留闸收到无界脏串、
④先于目录解析否则他空间探测得到存在性差分、①②先于③否则编码绕过文法）：

```
<!-- IG-4 ORDER-BEGIN
1 出现唯一性与字节卫生：同名参数/头多次出现、非法 UTF-8、NUL/控制符 ⇒ 传输层拒（不进门）
2 百分号规范化（框层）：通道框层解码至多一次；解出产物即值本体，必须重过第 3 步同一文法；
  解后仍含 %（多重编码）即拒；机制面自身不解码（含 % 的值 = 形态非法，纵深双闸）
3 形态闸：按参数类型套 IG-1 / IG-2 / REC_SCHEME / IG-3.2 卫生文法（逐字节，零规范化）
4 空间路由：入参 space 分量只作意图声明，与可信上下文注入值比对；不等 ⇒ 拒（同形，零存在性）
5 槽位类别：rec:/FR-/保留前缀串进对象引用槽 ⇒ 领域契约拒（FM-1.2）；解析器入口断言级拒
6 机制入口（构造期）：SpaceContext.spaceId 文法合法 + 出生绑定一致；违例 = 装配红
7 声明通道：保留前缀双检 ⇒ RECORD_ID_RESERVED；逐字节唯一性 ⇒ RECORD_ALREADY_DECLARED / ID_TAKEN（同形）
8 引用通道：记录未声明 ⇒ RECORD_UNDECLARED；目录解析不到 ⇒ NOT_FOUND_IN_SPACE（同形）
IG-4 ORDER-END -->
```

### 4.1 每一步的拒绝形态

- 步骤①②③④发生在**宿主传输层/装配层**（G2 Adapter 资产；本 PoC 无 HTTP 面，条文先行）：
  对外拒绝 = `TOOL_INPUT + detail.serviceCode`（X-3/M-3 既有过渡形 G-26，**不自造机制码、
  不自造 `F-*`**）；`serviceCode` 取值建议 `{ID_MALFORMED, ID_AMBIGUOUS_OCCURRENCE,
  SPACE_MISMATCH}`——detail 内字符串非新码（先例：`IDEMPOTENCY_KEY_REUSED` 只进工具 detail，X-2）。
- 步骤⑤–⑧发生在**机制内**：只用既有码（§4.2）。所有拒绝在**任何落行之前**（零残留：
  records/ledger/directory/journal 行数零变化——「拒绝不落行」既有纪律，FM-3.1(b) 同族）。
- 存在性 oracle 自检句：步骤③④的判据**不触及任何存储事实**（纯文法 + 上下文比对），故其
  拒绝形态天然不编码存在性；步骤⑦⑧与 D1-c 同形。**任何按 ID 的读写响应不得把他空间的
  存在与否编码进状态、detail 或时延**（SI-20 条件式同向 + G-19 五出口实测纪律）。

### 4.2 复用码论证表（每码：为何是它而不是别的）

| 场景 | 码（全部既有） | 为何复用它 |
